\section{Próximo gate}
Antes de qualquer futura claim científica: (1) formular o mecanismo estreito; (2) repetir a pesquisa com data de corte nova; (3) construir uma matriz de comparadores que separe overlap de mecanismo e equivalência de contrato; (4) congelar exactness, checkpoint, quantização, workload, budgets e métricas; (5) executar primeiro o teste barato que possa matar a hipótese; e (6) só depois medir no target físico.

Para residency/prefetch, o conjunto mínimo de comparadores conceptuais inclui MoE-Infinity, Eliseev--Mazur, EdgeMoE, ProMoE, SpecPrefetch, APEX, Cache-Aware Joint Router Adaptation, PreScope, ExpertFlow, FineMoE, DALI, Fiddler/KTransformers e os pipelines MoE-Lightning/Klotski \cite{xue2024moeinfinity,eliseev2023offloading,yi2023edgemoe,song2024promoe,kong2026specprefetch,kanani2026apex,wu2026cacheaware,yu2025prescope,he2026expertflow,yu2026finemoe,zhu2026dali,kamahori2025fiddler,chen2025ktransformers,cao2025moelightning,fang2025klotski}. Para a motivação de medir no dispositivo, consultar o benchmark de edge com âmbito explícito \cite{alfarizy2026consumer}; para speculation, Leviathan et al. é baseline algorítmico obrigatório \cite{leviathan2023speculative}.

Acrescentar Patterns Behind Chaos para prefill-aware placement/data movement, CoPilotIO para arquitetura GPU I/O com conclusão assistida pela CPU e Kairox para execução CPU/GPU baseada em activation sparsity \cite{yu2026patterns,chen2026copilotio,jiang2026kairox}. Separar esses comparadores pela unidade de placement e pelo stack avaliado; registar modelo, checkpoint, hardware, routing e se a métrica é de operador, de input fixo ou end-to-end antes de comparar números.

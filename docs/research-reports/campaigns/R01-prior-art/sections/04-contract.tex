\section{Contrato de exactness e comparabilidade}
No Tesy, o target real é autoritativo. Predictors/caches podem prefetch, ordenar, colocar ou propor; não podem substituir routing, reduzir top-k, omitir experts selecionados, confirmar tokens, mudar quantização ou truncar contexto. SpecPrefetch é particularmente próximo porque usa prediction para transferência antecipada e mantém o native router como autoridade de execução \cite{kong2026specprefetch}; isto constitui overlap direto e impede reclamar \emph{predictor apenas para prefetch} como novidade.

A proximidade de mecanismo não implica equivalência de contrato. Pre-gated MoE altera o gating/modelo para tornar a ativação antecipável \cite{hwang2024pregated}. EdgeMoE inclui adaptação de bitwidth \cite{yi2023edgemoe}; HOBBIT substitui dinamicamente cache misses por versões de menor precisão \cite{tang2024hobbit}; SiDA reporta eficiência com até pequena perda de performance do modelo \cite{du2024sida}; SwapMoE virtualiza experts sob budget ajustável e reporta ligeira perda de accuracy \cite{kong2024swapmoe}; AdapMoE altera dinamicamente o número de experts ativados \cite{zhong2024adapmoe}. Estes sistemas são related work obrigatório, mas não devem ser apresentados como baselines exactness-equivalent sem uma prova adicional de equivalência para o workload e modelo em causa.

FineMoE, DALI, ExpertFlow e PreScope são comparadores mecanicamente próximos para offload/residency/prefetch \cite{yu2026finemoe,zhu2026dali,he2026expertflow,yu2025prescope}, mas os seus papers não constituem, por si, prova do mesmo contrato bitwise/numerical/greedy/distribution usado pelo Tesy. A comparação deve separar dois eixos: desempenho sob o contrato declarado por cada sistema e equivalência demonstrada ao target Tesy. O mesmo vale para token reordering/scheduling: não se infere preservação só porque o router original continua presente.

Também os resultados de PowerInfer não transferem automaticamente para sparse MoE: o sistema explora sparsity/locality de neurónios em modelos compatíveis, não o routing exacto de experts do gpt-oss \cite{song2024powerinfer}. De modo análogo, um algoritmo de speculative decoding exacto estabelece prior art para preservação da distribuição \cite{leviathan2023speculative}, mas uma implementação Tesy futura teria de voltar a provar numerical/token/distribution preservation no backend e target escolhidos.

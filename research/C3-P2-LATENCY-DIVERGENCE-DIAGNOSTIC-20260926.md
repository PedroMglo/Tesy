# C3 latency-long divergence diagnostic (frozen before repeats)

The completed C3 preload latency run was resource-clean and solved all three synthetic tickets. Its 1522-token long prompt differed from the historical C2 no-preload run in reasoning text and total completion count (56 versus 55), although final JSON matched. The short and medium reasoning/final texts matched byte-for-byte. This is an **observed discrepancy**, not proof of a preload bug; cross-day free generations alone cannot identify where logits first diverged. It blocks broad promotion of preload pending explanation. The original run and comparator remain immutable.

Diagnostic D1: launch the already frozen C2 GPU8/32slot no-preload profile in a new monitored process. Use the unchanged `workloads/c2_latency_prompts.json`, its `latency-long` prompt only, context4096, medium/greedy seed42, max512, no prompt cache. Execute that same request **twice in order** in the same process, with separately named no-replace client outputs; record complete reasoning/final text, usage, timing and resource manifest. Do not compare just final ticket. Existing C2 launcher/stop scripts enforce 18 GiB cgroup/swap0, RSS17 GiB, GPU7000 MiB and 95/80/70 C thermal limits. No concurrent model process.

If both controls match the historical C2 output, one new preload repeat on the same frozen long prompt may test reproducibility of its variant, under a separate process/run ID. If the no-preload controls diverge from each other or from C2, label the cause unresolved and do not attribute it to preload. Free-generation comparison is a diagnostic only; a fixed-token logit/control experiment would be required for a numerical mechanism claim. Do not change thresholds, sampler or model to erase the mismatch. Budget ceiling and existing one-variable policy still apply.

## D1 observed result

`c3-d1-nopreload-long-server01` ran both requests and exited cleanly: 1080.843 s process wall, 14,856,298,496 B cgroup peak, 14,837,301,248 B RSS peak, 3869 MiB GPU, swap0, no stop or local/hierarchical max/OOM/kill event. CPU/GPU/NVMe maxima 90.25/57/57.85 C. The two responses reported 1522 prompt IDs, `cached_tokens=0`, 56 completion tokens and valid T029 final JSON each. Backend timers independently counted **1522 prompt-eval tokens in each request** (467.771 and 453.122 s), so the second request was not represented as a free prefix-cache hit despite the slot-selection LCP log.

Both no-preload controls had byte-identical reasoning and final text to the **new** preload run, while all three differed from the preserved historical C2 no-preload reasoning (55 tokens). `results/c3-d1-long-comparison01.json` is `HISTORICAL_VARIATION_NOT_PRELOAD_SPECIFIC` for free-generation text; it includes text hashes and raw-file hashes. This result **does not identify** the numerical cause of the historical variation or prove token-level/logit parity on the long prompt. It removes evidence for a preload-specific text change in these two controls only. The protocol's condition for a further preload repeat was not met, so none was run. Next discriminating correctness test, if needed for broader promotion: freeze the long prompt's token IDs and compare logits at the first divergent continuation position with matched kernels/placement, rather than compare free outputs after divergence.

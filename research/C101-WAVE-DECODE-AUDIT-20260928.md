# C101 wave decode attribution — source and existing raw

- **Objective/base:** Explain why C100 failed its protected decode gate without another model run. Base result commit `63021f9`; C35 source `c3759bad92c0e6f71bb936afea9b0a162fb83f76`; C75 source `27d2e42d8c994507ee6d71acc7c58d3eddd3f7a5`.
- **Evidence:** `results/c101-wave-decode-audit-20260928T2247Z/analysis.json` checks all C100 raw manifest hashes and records 12 request windows. C75 adds 24 source lines in two files: optional parked wave IDs on a host buffer and zeroed parked CPU MMID outputs. Relevant CMake cache deltas are the patch macro in C/C++ flags and `LLAMA_BUILD_TESTS`; all other GGML/LLAMA settings match. This is SOURCE_AUDITED plus reuse of C100 measured raw.
- **Alternative and result:** CPU thermal throttling alone is weak as an explanation for the warm decode regression: paired warm C75 CPU maxima were 64.75/65.125/65.375 °C versus C35 86.0/86.625/86.25 °C. Clocks and wave counts were not captured in C100, so neither the exact cause nor thermal exclusion is proven. The control and candidate are different binaries, leaving compile/build and wave behavior confounded.
- **Decision:** Freeze a two-pair C75 OFF/ON server A/B on the same frozen two-request input, same binary and libraries, alternating order with matched thermal starts. This is diagnostic attribution, not a new confirmation or candidate promotion. All older FAILs, C100 `NO_GO_CONFIRM`, M3 partial and M4 unmet remain unchanged.
- **Tests/limits:** `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tools python3 tools/c101_wave_decode_audit.py` passed; output no-replace. No model was loaded; no new physical timing. Next gate requires a clean measurement commit, E18 admission and complete same-profile output/resource checks.

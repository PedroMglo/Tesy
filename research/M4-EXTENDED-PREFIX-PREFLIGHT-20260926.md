# M4 extended fixed-prefix diagnostic: prospective record

Objective: strengthen target numerical coverage after the completed M4/M5/M6 campaign by testing the entire fixed Harmony prompt already embedded in `tools/logits_probe.cpp`, rather than its first four tokens. This is a diagnostic gate, not a new performance workload, a changed model, or an optimization intervention. Lab base commit `f8be501356633c337fee8b9737f7606d4a82817c`; original candidate source SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, isolated reference loader patch SHA `e5230b922aa4b4b410b2aaa38bd291fe9bd40bcd`. The reference patch only disables eager mmap prefetch via `TESY_MMAP_NO_PREFETCH=1`; the prior four-token patched-versus-unpatched 20B reference yielded bitwise-equal logits. Target GGUF SHA-256 and revision remain as locked in M4.

Fixed input: the entire tokenization of `<|start|>user<|message|>What is 7 plus 5?<|end|><|start|>assistant<|channel|>final<|message|>` by the target GGUF tokenizer. No `TESY_LOGITS_PREFIX_TOKENS` limit is set. Both modes use CPU0 placement, same model, context4096, microbatch32, eight threads, no repack and op offload disabled. Plain mode uses the isolated no-prefetch mmap reference; stream mode uses original candidate O_DIRECT, 24 slots per layer and no preload. Each fresh process runs under an enforced 18 GiB cgroup, zero swap, RSS17 GiB, GPU7000 MiB, MemAvailable6 GiB watchdog and 600-second timeout. Runs are sequential under IDs `probe120b-fullprefix-ref01` and `probe120b-fullprefix-stream24-01`; outputs are `results/` with large float32 rows and raw logs untracked.

Primary metric fixed before execution: complete final-prefix float32 logit row **bitwise equality**, same exact token IDs/count, finite values and 201,088 vocabulary positions. Any mismatch, resource event, error or incomplete manifest blocks promotion of this extra numerical coverage; no tolerance change or alternate prefix after observation. Compare through `tools/compare_logits.py` into `results/probe120b-fullprefix-compare01.json`. This checks one longer prefilling prefix and later routed states than the four-token probe; it cannot certify all 256-token decode trajectories, GPU8 versus plain CPU arithmetic, cache lifetime under every eviction order, or task correctness. Alternatives: per-token full-logit rows would require probe changes; a full stock GPU8 120B reference exceeds VRAM, so this bounded same-kernel CPU comparison is the cheapest next check.

# C3 P2 preload sustained server gate

Frozen after the three-pair prefill result at lab code before launch. A/B `results/c3-p2b-ab-summary01.json` passed its prospective reproducible-smaller-gain criterion (median 17.515% at 496 IDs, 18.240% at 1522 IDs; all pairs faster) and **failed** the 25% goal. This server run tests whether that candidate remains correct and useful under continuous generation; it does not retroactively turn the prefill result into 25%.

Target is the unchanged GPT-OSS 120B MXFP4 GGUF, pinned streaming backend and server binary, GPU8/32 expert slots, context4096, batch256/ubatch32, CPU8/I/O4, direct I/O, no repack/op offload, official medium Harmony template, greedy temperature0/seed42, one request at a time, no prefix-cache reuse. Preload is enabled by **removing** `LLAMA_MOE_STREAM_NO_PRELOAD` from the server environment; all other settings match C2's 32-slot sustained profile. One server on 127.0.0.1. Preflight records full model hash already verified, binary/libraries, exact launch PID/cgroup and tokenization/template settings. No model processes overlap.

The workload is the same fixed historical ten synthetic tasks twice in the same order as C2-C: twenty requests, max completion512 each, including reasoning. This is a regression and service test, not new held-out quality. The new protocol has its own ID `c3-p2-preload-sustained20-v1`, outputs no-replace, total timeout3600 s, >=900 s process and active service, >=600 s decode, all twenty requests complete, aggregate and second-half decode >=3.000 tok/s without rounding. EOS/cap completions and failed task answers remain counted. No sleeps extend duration. Compare the raw assistant reasoning/final content, finish reasons, API prompt/completion counts and task IDs byte-for-byte with the preserved C2 no-preload twenty-request raw file. Any unexplained mismatch blocks promotion even if the throughput gate passes; full plain-model parity remains outside this scope.

The resource envelope is memory.max18 GiB, swap.max0, RSS17 GiB, GPU<=7000 MiB, MemAvailable>=6 GiB, CPU/GPU/NVMe<=95/80/70 C, ~1 s samples with <=3 s adjacent gaps and <=2 s boundary gaps, zero local/hierarchical max/OOM/kill event deltas. A run with missing telemetry, backend error, swap, OOM, guard violation or incomplete twenty requests fails. Normal thermal behavior stays in the result. The existing strict C2 gate/publication primitives are reused under a new C3 campaign ID; historical C2 gates remain immutable.

Report process wall, active time, prefill, decode, load, per-request and last-half throughput, final-answer success/truncation, sampled resource peaks, thermal windows and process read_bytes distinctly from physical NVMe traffic. Per-token p50/p95 and first final content are NOT_MEASURED by this nonstreamed server protocol; a separate latency protocol would be required. The C2 run is a practical historical comparator, not a same-day causal sustained A/B. If the new run fails, default remains the C2 no-preload profile.

# C3 slot-generation witness protocol

Frozen before run `c3-r2-generation-log01`. The broad numerical references and their source captures remain unchanged. This additional target diagnostic uses the same `log_medium` IDs, model/backend, GPU8/32 slots, ubatch32, direct I/O, no preload and resource envelope as the broad capture, but records only layers 0 and 35 at initial prefill and first decode. The diagnostic capture binary SHA-256 is `453f253408c124cd434ffda07c8b375ad3f71220e3b881b22c6837fba3824248`; it links the pinned backend's private `llama_moe_stream_layer` definitions only for observation, without changing its implementation.

At each remap/wave-ID callback completion, copy physical slot IDs and, under the cache manager mutex, their current `slot_gen`, `slot_expert` and state. At the corresponding consumer callback, require every active logical expert to have its physical slot RESIDENT with the same expert and positive generation, then compare all three encoded matrices and three logical biases with canonical GGUF slices. Masked parking pairs are excluded. The witness sought is at least one physical slot reused for a different logical expert at a strictly larger generation within the first prefill microbatch, plus exact bytes for both occupancies. Absence is `NOT_OBSERVED`, not a PASS. The callback's lock/synchronization can mask a race; this test does not prove all in-flight schedules.

The two full 201,088-float32 logits rows at prompt position31 and continuation position189 must remain bitwise equal to the prior callback-OFF run `c3-r2-parity-off01` under the same IDs/configuration. A new comparison output root is no-replace. Any callback failure, ID/generation inconsistency, byte mismatch, resource violation or non-finite vector fails this run. Raw stays local. No production throughput claim.

# Target numerical diagnostic gate

Prospective decision after `target120b-gpu8-smoke01` returned successfully. Objective: compare final-prefix float32 logits for the verified 120B GGUF on the same candidate SHA with streamed expert weights versus ordinary `mmap` weight lookup. This is a diagnostic gate before the longer two-request M4 run, not a performance intervention (optimization budget remains 2/6 cumulative). Base lab commit `c36c59306c6e49ababd4db137420700bc6a8856f`, source backend unchanged at `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`.

The existing 17-token probe would make a plain 120B load with `use_mmap=false`, materializing 60+ GB; that violates the host guard. Tool-only changes allow a prospective four-token prefix from the same fixed Harmony token sequence and `mmap` for plain mode. Both modes will use CPU placement, 16 slots in stream mode, `--no-repack`, op offload disabled, 4096 context, one sequence, microbatch 32, the same model SHA and source SHA, under an 18 GiB cgroup with swap prohibited. Stream reads use O_DIRECT; plain uses `mmap`. The prefix is deliberately short so page residency remains bounded. The metric is bitwise equality of the complete final-logit row; any difference is a failed equality claim and must be quantified, not hidden by a widened threshold. Rejection criteria: nonfinite logits, resource event, OOM, swap, unverified binary/artefact, or differing token IDs. This checks one fixed early prefix only; even equality does not prove all decode states or routed-index lifetimes.

First verify that the modified probe still handles 20B and records the chosen prefix. Then run target stream and target plain, each with a separate run ID. If the plain `mmap` reference cannot complete within the guard, retain the timeout/resource failure and do not claim 120B numerical parity. Previous 20B full-prefix parity remains separate evidence.

## Prospective diagnostic patch after the failed plain reference

The plain `mmap` 120B reference failed its 17 GiB RSS guard during model load; the four-token prefix was not reached. The same-SHA source calls `init_mappings(true)`, which invokes `MAP_POPULATE` for the whole file. This is a prefetch side effect, not part of routed arithmetic. Prepare a separate worktree from the same backend base SHA with a one-line conditional to disable this prefetch only when `TESY_MMAP_NO_PREFETCH=1`; retain the original build for the stream side. Metric: complete final-prefix float32 logit equality for the same four token IDs. Prohibited regressions: weights/quantization/router/top-k/kernel change, extra host/GPU resource use outside guards, swap/OOM, or missing prefix provenance. The reference will use CPU-only placement and the same microbatch. This patch is diagnostic, not a throughput optimization; it does not count as an M3 intervention. If the patch cannot produce a bounded reference, target parity remains unknown. Do not alter the four-token comparison threshold after output.

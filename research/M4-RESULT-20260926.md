# M4 bounded target result

Objective: execute the locked GPT-OSS 120B MXFP4 GGUF above physical RAM with exact routed expert streaming. Base lab checkpoint `efa8227e503a6b3fb74427c7c49f18e8808b2727`, original candidate SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, binary SHA recorded in `results/target120b-gpu8-two-turns01.json`. Target full-file SHA-256 was verified before execution. Evidence classes below are measured unless labeled source audit, inference, or unknown.

## Execution and correctness coverage

`tools/run_target_two_requests.sh target120b-gpu8-two-turns01` was executed on the physical Fedora Ryzen AI 9 HX 370 / RTX 4060 Laptop host, with the 63.39 GB GGUF on `/dev/nvme0n1p3` btrfs. Two distinct prompts in one original candidate process completed by natural EOS, with up to 256 tokens permitted each. The model is larger than 30 GiB physical RAM. Candidate source redirects only the routed expert weight tensors into 16 slots per layer, against 128 logical experts per layer; bias tensors remain indexed by logical ID. The tensor sizes and full-file checksum are recorded in the preflight. O_DIRECT expert descriptor was observed throughout decode. This is source audit plus runtime evidence of bounded expert residency, not a formal proof for every route.

The fixed target prefix `[200006,1428,200008,4827]` produced 201,088/201,088 bitwise-equal final logits between original candidate streaming and a plain same-base CUDA build with only mmap prefetch disabled. The diagnostic reference patch was independently checked on 20B. This numerical claim covers exactly one four-token CPU prefix, microbatch 32, no repack/op offload. It does not certify all generated tokens, GPU arithmetic or arbitrary prompts. No silent expert substitution/top-k reduction/quantization change was introduced. There is no full-decode stock 120B reference within the host budget. The original unpatched plain target reference hit its RSS guard before inference and remains a failure.

Functional results are separate: request 1 solved `17*23` with final `391` (PASS); request 2 returned syntactically valid JSON and correct `city`/`amount`, but `day` was `"26 September 2026"` rather than the specified number `26` (FAIL). This failure is retained; no validator or prompt was changed after observation. Coherent text alone is not numerical parity.

## Resources and timing

One sequence, context 4096, batch 256, microbatch 32, GPU8, per-layer 16 expert slots, four direct I/O workers, greedy seed 42, no preload/repack/speculation. Cgroup `memory.max=18 GiB`, `memory.swap.max=0`. Peak `memory.current` 9,627,729,920 bytes, RSS 8,694,730,752 bytes, charged file 2,808,901,632 bytes, GPU total use 2406 MiB. Zero process/cgroup swap; zero cgroup max/OOM events. Highest sampled GPU temperature 59 C, not a sustained thermal equilibrium measurement. Runtime elapsed 298.215 s, stop reason null.

| `17*23` | 84 tokens / 49.494 s = 1.70 tok/s | 158 tokens / 70.846 s = 2.230 tok/s | PASS, natural EOS |
| extraction | 201 tokens / 113.669 s = 1.77 tok/s | 114 tokens / 57.054 s = 1.998 tok/s | FAIL specified `day`, natural EOS |

The backend prints 2.00 tok/s for the second decode after rounding; the exact rate is 1.9981106, below the >=2 target. Neither request is a 256-token decode or a 15-30 minute sustained observation. TTFT and first useful final answer were not separately instrumented. No M5 claim is made. The second prefill includes conversation context reuse; rates are reported with that condition.

The last sampled `/proc/PID/io:read_bytes` was 398,831,923,200 bytes for load, prefill and decode together. Samples show it rising throughout both decodes. This is process-attributed block read accounting, not exclusive physical NVMe traffic or exact expert payload. The candidate has no reported RAM tier and no full-run hit/miss counters yet. H2D bytes, evictions, ready-versus-in-flight hits and exact I/O stall fraction remain unknown; M2 is partial. The internal NVMe identity is verified, but background/shared device traffic is not excluded by this counter.

Decision: bounded M4 over-RAM mechanism is demonstrated for this artefact, resource budget and two requests, with explicitly limited target numerical coverage and one functional task failure. Do not promote a 2 tok/s sustained or larger-model task-benefit claim. Next gate: instrument target hit/miss and wait counters with a diagnostic-only source patch, measure a comparable run, then choose one optimization by measured bottleneck. Existing stock 20B comparison is practical surrogate evidence only; no 120B stock speedup is computed.

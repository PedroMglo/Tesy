- Objective: validate completion-fenced streaming and exact-prefix reuse under P12 at n_ctx8192. Measurement commit `299052f4d4f2a494a3281b35f65ed2f03e89afb6`; original backend/model and E18 zero-swap profile unchanged from C26. - Measured: official prompt IDs 2035/2163, common prefix 2026; second request cache_n 2026. Both SSE requests completed with `[DONE]`, usage, timings and finite outputs. Cold request completed in 289.676 s, prompt 274.379 s, decode 3.401 tok/s. Incremental request completed in 37.858 s, prompt 22.801 s, first non-whitespace text 23.402 s, first final content 37.643 s, decode 4.054 tok/s. These are client receipt times, not per-token server timestamps. Compact evidence is in `results/c27-session-bridge-20260927T2220Z/` and raw is local/ignored.
- Resources: CPU max 95.125 C (warning only), GPU 62 C, NVMe 54.85 C, GPU total 5752 MiB, RSS max 13291122688 B, cgroup peak 13073215488 B, zero swap/OOM, processor cooling state zero. One 332.813 s bounded server run with 300.535 s admitted idle; no sustained thermal claim.
- Decision: `PASS_BRIDGE_SYNTHETIC_SCOPE`. The prospective M4 incremental targets of <=10 s first final content and >=6 tok/s decode are not met in this case. M3 remains partial: this was one growing synthetic user message, not true conversational history, 4096-prefix coverage or the 60-minute/20-request regime. M4 quality and task tests NOT_RUN. C15 remains source-only, default unchanged.
- Alternatives: prefix caching eliminated reprocessing of 2026 IDs but 137 prompt IDs still cost 22.801 s and 61 output tokens cost 15.048 s. Full-session template continuity may expose different cache behavior; waves or native placement might reduce prefill/decode. The next low-cost discriminating gate is a two-turn server bridge that preserves the actual generated assistant turn and checks official template IDs/cache, followed by a decision on 4096-prefix/sustained testing versus bottleneck profiling. No claim of causal speedup from this single arm.

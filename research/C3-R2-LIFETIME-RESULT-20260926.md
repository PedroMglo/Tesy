# C3 R2 lifetime, negative and callback gates

**MEDIDO_NO_TARGET:** run `c3-r2-generation-log01` observed the pinned stream manager's slot state under its mutex at actual consumer callbacks. All 468 active tensor slices (1,033,793,280 encoded bytes) equaled independent GGUF reads. Layer 0's first prefill microbatch reused 30 physical slots for different logical experts at strictly increasing `slot_gen`; e.g. slot 0 held experts 30/107/76 at generations 1/2/3. At each checked active pair the manager reported RESIDENT with the matching logical expert. Run completed without swap/OOM/guard stop, cgroup peak 15,310,352,384 B, sampled GPU peak 3898 MiB. Its prompt position31 and continuation position189 full logits are bitwise equal to callback-OFF in `results/c3-r2-generation-parity01.json`. This observer acquires the manager mutex and can change race timing; it does not certify all asynchronous schedules.

**REPRODUZIDO_MODEL_FREE on pinned implementation:** `c3_stream_lifetime_test` used the actual `reserve_slot_locked`, `pick_victim_locked` and worker queue methods. A deliberately stale queued generation was skipped; a LOADING slot was excluded from victim selection; current generation published. It used no actual I/O. `c3_inflight_read_test` held an actual buffered `pread` on a disposable authorized fixture while the pinned worker owned a LOADING slot; the victim selector excluded it, and after release it published the correct fixture bytes. These are deterministic tests of this backend's worker and cache logic, not a GPU upload failure test. Test binary SHA-256 values are in the build output and final evidence index.

**MEDIDO_NO_TARGET expected failures:** the test-only observer mutations `wrong_id`, `stale_byte` and `bias_index` each emitted exactly one injection marker and exited 1 before completing output. Their audit files record `PASS_EXPECTED_BEHAVIOR`, but the model invocations remain failed diagnostics. The pinned read interposer, armed only after context load, injected one EIO, EOF or 4096-byte short read; each target process aborted with `expert load failed (I/O error)`, return code -6 and no completed capture. No model weight was changed. All six negative runs had zero swap/OOM. One 200 ms delayed-read target run completed with all 468 bytes equal, 30 slot generation reuses, zero swap/OOM and both full logits rows bitwise equal to the callback-OFF control (`results/c3-r2-negative-delay01-parity.json`). This delay was on one read and is not a proof of every in-flight interleaving.

**SYNTHETIC_MUTANT:** `c3_omit_wave_fixture.py` used the actual first-wave `down_biased` output, wave mask and routing weights from a real capture, then subtracted that wave's contribution from a disposable FFN output. It removed 36 active pairs and changed 54,720 output cells (maximum removed contribution 33.02016449). The canonical layer-0 reference returned 1: routing IDs/weights still bitwise equal, prefill FFN max absolute error 33.02016449, decode FFN bitwise equal. Original raw capture hash remained unchanged. This validates the FFN oracle's sensitivity to a missing wave in the tested shape; it is not an actual backend omit-wave bug.

**MEDIDO_NO_TARGET callback parity:** OFF controls for `log_medium` and `spec_pressure` completed with 49 and 62 complete float32 rows respectively, zero swap/OOM. The fail-closed comparator matched seven preselected full 201,088-float32 vectors per case to the previously completed broad ON captures; **14/14 BITWISE_EQUAL**, with finite values and exact row/position identity. Results: `results/c3-r2-broad-parity-log-comparison01.json` and `results/c3-r2-broad-parity-spec-comparison01.json`. This is full-model streamed OFF/ON parity at selected positions, not a plain-model full-prefix reference.

The backend aggregate OFF log for `log_medium` reported 7,583 expert hits and 6,778 misses (3,014 cold) across 1,764 remap calls, and 2,065 wave calls (686 nonempty). Its hit counter includes experts LOADING as well as RESIDENT, so it does **not** by itself prove a ready-hit class. Misses beyond first touch establish reload activity only at aggregate scope. The explicit pre-remap class witness and GPU upload fault remain open. No P1/P2 optimization has been run.

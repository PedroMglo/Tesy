# C8 native next-wave preload protocol

- Objective: determine whether the pinned backend's existing next-wave preload reduces completed P8 prefill for the frozen 496-ID case while retaining the same routed computation. This follows C7c `NO_GO_SCREEN496` for P12 general-medium timing; C7c is preserved. Base before C8 code: `de27975eb7456fc69fca2822d1570fb3773dd6e0`, original backend `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, tree `8219dfba2414cdcbb388e43b1c67a49f1f70e4aa`. Measurement commit is frozen by committing this source/protocol before the first C8 process.
- Hypothesis: overlap of the next wave's expert loads with current wave computation reduces demand wait and prefill. Alternative: queue contention, evictions or increased decode cost cancel the overlap. Historical C4 long OFF/ON logits were bitwise at five checkpoints and one diagnostic ON prefill was 367.56 s versus OFF 442.11/446.29 s. That evidence selects this test; it is not a paired confirmation, and historical resource/library receipts remain limited.
- Single variable: P8 native original backend, `ngl8`, ub32, slots32, E18, unchanged model/weights/routing. OFF has `LLAMA_MOE_STREAM_NO_PRELOAD=1`; ON has the variable absent. All other effective options, external calls, IDs, masks, KV clear and placement are frozen in `results/c8-20260927T1305Z/protocol.json`. The ON source only reserves experts in the existing 32-slot pool; additional observer allocation remains bounded by guards and measured.
- Numeric gate: fresh OFF1, ON capture, OFF2 on `log_medium` 189 prompt IDs in one external call and 32 teacher-forced one-ID calls. Five complete 201088-F32 logits vectors must be bitwise across arms; OFF1/OFF2 all 33 rows must also repeat bitwise. The capture must have 250 numeric states and two explicit masked states, valid bytes/generations/lifetime witnesses, and 36 canonical resident references using the P8 CPU0–28/GPU29–35 map. Start references at layers 25–28 and 0/29/35. Any numeric/resource/evidence error closes the unit with raw preserved; no timing promotion.
- Timing plan if numeric gate passes: two alternating fresh-process pairs at 113+32 as a behavior check, then two at 496+32. Paired gain is `100*(OFF−ON)/OFF` per pair, then median of pair gains. Medium screening needs median prefill ≥10%, both prefill pairs positive, median T_work ≥8% and median TPOT ≥−5%. A survivor needs three new 496 pairs with prefill median ≥12%, T_work median ≥10%, all work pairs positive and TPOT median ≥−5%. A bounded 1522 check follows only after confirmation. C8 does not reuse C4 diagnostic clocks for a causal claim.
- Evidence class now: source/static feasibility and historical diagnostic selection. The source counter named ready on arrival increments for an already resident expert and does not prove a successful preload; wave stall is accumulated callback wait, not an exclusive critical path. `pread` and `/proc/PID/io` are application accounting, not physical NVMe traffic. Screens use synthetic teacher-forced steps and say nothing about API TTFT, quality or sampling distribution.

Prior P8 496 maxima were GPU3900 MiB, cgroup14.760 GB and RSS14.963 GB. If admission, exactness or telemetry fails, preserve the failure and select another independent hypothesis. Ub64 and serving/prefix reuse remain open, not combined into C8.

# C38 functional qualification protocol

- Objective/base: start the initial utility comparison after C37 synthetic session retention. Base `d988d48d55e3c19c4e634112f9a41adaa211f646`; measurement commit is the following protocol commit. P8/P12 use the isolated C35 backend with fixed template render date, preserving its model graph and routing; the 20B uses its clean stock backend and existing verified model SHA. All three are separate profiles under 8K context, medium effort, greedy seed 42, 3072 output cap, one task per request with no prefix reuse.
- Evidence class: prospective protocol and model-free validator evidence only. `workloads/c38_quality12.json` contains 12 new synthetic tasks, four each in code, SQL/data, and planning. They are not user history. `tools/c38_quality_grade.py` runs code/SQL in the existing no-network isolation and checks planning JSON exactly. Twelve gold controls pass and twelve mutants fail.
- Hypothesis: P12 will resolve every task solved by P8, under the same output/time budget; the 20B gives a useful speed/quality comparator. No expected pass count or speedup is assumed. The alternative is a numerical/profile quality loss, timeout, truncation, or resource failure. Each task has a 600 s functional deadline; report valid solutions by 30/120/600 s.
- Capacity: historical 20B ngl14 in 4K reached 6578 MiB GPU. C38 uses ngl13 as an explicit new 20B profile. The effect of 8K KV/workspace is unknown; init-only and a one-request monitored capacity smoke must pass the 6500 MiB reservation before the full 20B suite. P8/P12 8K allocations have prior monitored evidence. E18, zero swap, CPU95 warning/100 stop, GPU80/NVMe70, MemAvailable >=6 GiB remain in force. No power/clock change is planned.
- Order/decision: stock20 init, stock20 smoke, stock20 full, P8 full, P12 full. Every process is fresh, with a new thermal idle admission and no hidden retry. One run per arm produces descriptive timing; it cannot establish a stable speedup. M4 additionally requires all critical tasks plus session/context and resource gates, so this suite alone cannot certify it. Failure receipts remain. C15 full-model tracing stays NOT_RUN while this utility gate is pursued.
- Checks/NOT_RUN: validator controls and frozen-source comparison PASS. All model requests, quality grades, 7936+256 boundary, true assistant-history sustained session, and C15 model trace are NOT_RUN at protocol freeze. No default or remote state changes.

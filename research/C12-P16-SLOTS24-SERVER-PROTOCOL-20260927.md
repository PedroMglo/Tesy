# C12 P16/slots24 8K server resource protocol

- Objective/base: test whether a native P16/slots24 8K full-SWA server can move four more streamed layers from CPU to CUDA and complete a cold 513-ID request with thermal margin. Base `14e61467ec9ed28571ee882aabdbfbcf76ae20e0`; measurement commit contains this freeze. C11 P12/slots32 completed one 513-ID request but reached CPU 95.0 C with zero thermal margin. C9/C10b P8 513-ID guards failed and remain preserved.
- Hypothesis/alternative: extra GPU layers may reduce CPU heat and critical work. The coupled slots reduction changes the graph wave capacity and may increase misses, callback work, prefill time or numerical reduction order. No pure placement attribution is possible versus C11. If resource admission passes and timing is later considered, P12/slots24 must be added as an interaction control before attributing a speedup.
- Source/static feasibility: the original backend accepts exact slot counts through `--moe-stream-cache Ns`. With n_expert_used=4, full ub32 touch maximum 128, graph wave cap is `(slots−4)/2`: 14 experts/10 worst-case waves at slots32, 10 experts/13 waves at slots24. Slots24 satisfies the source's ≥12 minimum. GGUF tensor inventory gives P16/slots24 GPU pools 4,758,912,000 B versus P12/slots32 4,653,158,400 B; four more nonstream layers add 136,620,032 B. Applying this delta to C11's 5746 MiB peak yields ~5977 MiB before changed workspace, under the 6500 MiB reservation. P16/slots32 predicts ~7490 MiB and is not admitted. Actual workspace, cache misses and thermals remain unknown.
- Frozen profile: original backend pin/model/ub32, preload ON, 8K full SWA, E18, same synthetic inputs and output cap as C11; relative to C9 server argv only `-ngl 8→16` and `--moe-stream-cache 32s→24s` change. Expected map is CPU0–20/GPU21–35 plus output, pending loader observation. This is a separate numeric profile; C7/C8/C11 references do not certify its wave plan.
- Sequence: bounded init-only (120 s), 78-ID/four-token minimum forward (180 s), 513-ID/four-token cold request (300 s), each own clean measurement commit and scope. Systemd E18 memory.max, swap.max0; RSS ≤16 GiB, cgroup ≤16.5 GiB, GPU ≤6500 MiB, MemAvailable ≥6 GiB, CPU/GPU/NVMe ≤95/80/70 C, start CPU ≤55 C, telemetry ≤1 s/endpoints required. Stop and preserve on any guard/evidence failure; no retry under this identity.
- Decision/limits: resource diagnostics only. Exact logits, same-device canonical layer, prefix reuse, paired timing, functional quality, 8K boundary and sustained session are NOT_RUN. If resource-valid and thermal margin material, build the P16/slots24 same-profile numeric gate before timing; if not, pursue an independent critical-path or serving-profile hypothesis. Default/usual server unchanged.

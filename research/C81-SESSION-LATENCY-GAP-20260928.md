# C81 — Prefill-only improvement does not close the session latency gap

- Objective/base: quantify which M4 latency target remains after a prefill-only intervention, using existing C52b and C74 evidence. Base Tesy `bcd024c` plus the prospective `hypothesis.json` in `results/c81-session-latency-gap-20260928T1942Z/`. Evidence class INFERIDO from hash-verified MEDIDO_NO_TARGET inputs; no model execution.
- Alternative: the C52b post-prefill time could already be under 10 s. It was not: for all 19 incremental requests, client first-final-content time minus server prefill duration exceeded 10 s, with median 15.761 s. Median first-final was 41.464 s, prefill 25.925 s, decode 3.753 tok/s. To reach 6 tok/s at the same token count, TPOT would need to fall 37.46%. C74 teacher-forced probe measured 1.44% median decode-time gain from wave skip, a separate profile that is not a server forecast.
- Decision: preserve C74's confirmed prefill gain and continue the C75 session bridge, but prioritize decode demand/wait and bounded residency after numeric admission. A counterfactual with zero prefill and fixed post-prefill residual still misses 10 s; this arithmetic is not a physical lower bound under changed runtime, workload or quality. No claim of causal NVMe cost, M4 or default adoption.

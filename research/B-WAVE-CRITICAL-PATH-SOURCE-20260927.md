# Wave/parking critical-path feasibility checkpoint

- Objective/base: decide whether a localized wave compaction prototype is justified after C11/C12 513-ID server diagnostics. Base `b69ccb96944368e17b55ea6964cea5bb9cd0296b`; original backend remains `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`. Evidence class: source/static plus earlier diagnostic profiler summaries, no new model run.
- Source: `src/llama-graph.cpp` computes each wave's expert GEMMs over the full top-k/token layout, then multiplies by a wave mask and sums wave outputs. The graph plan bounds simultaneous current/next/parking experts by `(slots−top_k)/2`. For this model top_k=4 and ub32, slots32 permits 14 experts/wave and at most 10 waves; slots24 permits 10 and at most 13 waves. `src/llama-moe-stream.cpp` stages the selected experts and parking slots while retaining routing IDs for weights/biases. This creates a plausible opportunity to avoid arithmetic for masked token-expert pairs, with numerical-order and lifetime risks.
- Existing evidence: C4 perf samples attributed 81.81% of user cycles to `ggml_vec_dot_mxfp4_q8_0`, but call-stack attribution to masked pairs was incomplete. C4 Nsight GPU kernel/memcpy durations did not cover CPU GEMM/I/O; summed spans overlap. C8 paired P8 preload-on improved 496+32 T_work 16.59%, showing I/O overlap matters, but does not measure removable wave work. Backend `wave stall` counters are overlapping waits, not an exclusive wall-clock fraction.
- Decision: the exclusive critical-path fraction `f` and removable fraction `r` are still UNKNOWN, so the requested bound `f*r−h` cannot be quantified. Do not implement compaction from callback counts or cycle shares alone. A discriminating next B unit would instrument scoped per-wave CPU GEMM spans and I/O/CUDA overlap on an isolated backend build, compare its output to an uninstrumented bridge, then derive an exclusive wall-time bound before changing arithmetic. That unit needs its own pin/protocol and remains NOT_RUN.
- Independent next line: exact-prefix reuse has a frozen C9 mechanism runner and directly targets repeated-session latency. C11 P12 completed the first 513-ID request once under E18, enabling a bounded two-request mechanism diagnostic now. This does not satisfy the B bound or promote P12 numerical/server timing claims. C12's no-margin profile is not carried forward.

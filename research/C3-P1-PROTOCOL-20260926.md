# C3 P1 prefill diagnostic protocol

Frozen before new P1 model runs. R3 allowed measurements on the unchanged production boundary at lab commit `e33795bc1d0f935b2ac22fde536330370bd3d502`. Target/model/backend SHA, GPU8/32slots, context4096, batch256/ubatch32, threads8/I/O4, O_DIRECT, no preload/repack/op offload, memory.max18 GiB, swap.max0, RSS17 GiB, GPU7000 MiB, MemAvailable6 GiB and 95/80/70 C guards remain unchanged. No performance intervention has yet been made (0/4). P1 diagnostics do not alter the default.

Input source is `workloads/c2_latency_prompts.json` (SHA-256 to be recorded at tokenization), in fixed short→medium→long order. A bounded localhost pinned server applies the same medium GPT-OSS Harmony template and `/tokenize` implementation used in C2-D, saving complete token IDs in a new no-replace file. Require exactly 113/496/1522 IDs as previously observed and prompt+512 <=4096; a count mismatch ends this protocol. Stop the server before any probe. No new model weights are downloaded.

A separate native prefill-only diagnostic feeds those IDs through the pinned backend in one process with KV cleared between cases and expert cache retained, decoding prompt chunks of at most batch256 internally split by ubatch32. It records wall time for each `llama_decode` chunk, cumulative backend expert hits/misses/cold/wave/wait counters after each chunk and resource telemetry; it does not generate a final answer and does not replace the C2-D client TTFT measurements. First run is uninstrumented (apart from stats at chunk boundaries), second uses a test-only interposer for `pread` requests/returns and `ggml_backend_tensor_set` cache upload requests and completion wall times. The interposer records only while a prompt chunk is active. Binary/library identities, exact IDs, raw trace cap and hashes are separate. Comparing the two paths measures instrumentation overhead and final logits at each prompt end must be bitwise equal. If overhead is large, trace timings are diagnostic only.

The analysis maps read offsets to real GGUF expert tensor ranges and cache tensor names to layers, reporting encoded bytes requested/returned, upload bytes requested, per-layer/chunk events and times, and separately process `read_bytes` and resource peaks. Requested/returned syscall bytes are not exclusive physical NVMe traffic. Upload requests and wall time are not physical PCIe bytes or disjoint GPU time. Overlapping waits/compute/transfers are not summed as an exclusive wall-time partition. This phase chooses at most one first P2 candidate from the largest measured avoidable component; no new throughput claim until a prospective A/B.

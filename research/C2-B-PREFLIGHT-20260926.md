# C2-B target numerical/reference protocol

Objective: extend the one four-token logit row from campaign 1 to fixed teacher-forced positions and an explicit second KV request. Base C2 lab commit `e53d376`, backend stream SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`; independent diagnostic reference worktree is detached at `e5230b922aa4b4b410b2aaa38bd291fe9bd40bcd`, whose sole inherited source change disables `MAP_POPULATE` when `TESY_MMAP_NO_PREFETCH=1`. This reference change was previously checked bitwise against unpatched plain mode on the 20B four-token prefix. No routing, weights, quantization, context, attention, KV or sampler patch is made.

The selected 120B MXFP4 GGUF was rehashed by read-only O_DIRECT sequential reads in C2 and matched `582bd40f6886200101f4c4ed9f25f3fe80cc14c86e9e2b37746cd8904a0c622d`, 63,387,346,208 bytes. The official model vocabulary tokenized `workloads/c2_numeric_cases_v1.tsv` (SHA-256 `09c35d5c7df557e066ec6e81483479fde81cc29c11e0c673221f9379b98ec805`) exactly once to `results/c2-target-numeric-v1.ids` (SHA-256 `8fb3aff447febaeaa5a8bdd0c485fd20d51d39fb6ac3e6ba4849eb4a664dbc23`). Cases are quantitative short 110 prompt +26 continuation IDs, log medium 189+43, and specification pressure 414+49. The prior oversized draft at `workloads/c2_numeric_cases.tsv` (SHA-256 `437e693e78a730ea7f5d14edfe9b2d7b06ad0c342a7b59d4fefe27e69b173618`) and its tokenizer run remain as a diagnostic, not a timing or correction result. The revision followed only token counts before any model decode.

Both sides consume these identical IDs. Use llama.cpp's `llama_decode` with explicit positions and sequence ID 0, n_ctx4096, n_batch256, n_ubatch32, eight CPU threads, no op offload, no extra weight repack. Prompt chunks end at every 32nd token (last shorter chunk included); every continuation token is an incremental decode and its complete 201,088-element float32 row is stored. Clear KV between cases in the same process while retaining model/expert cache. This gives multiple positions, microbatch boundaries, attention-local boundaries within the longer cases, and second/third requests; a length alone is not evidence of cache churn, so demand/miss diagnostics must be read separately. Input ID file, row index and full row file hashes are required. First contract is BITWISE_EQUAL for matched CPU kernels. Unequal rows or nonfinite values fail the gate; report max/RMSE/top1 separately, with no retroactively widened tolerance. Distinguish this from task quality and free-generation equality.

Reference policy **REFERENCE_RECLAIM_ALLOWED**: same 18 GiB cgroup and zero swap, but `memory.events:max` increments may indicate direct reclaim. [Linux cgroup v2 documentation](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) defines `max` as a charge about to exceed the boundary, with OOM only if reclaim cannot bring it down; `memory.peak` records high use. The old `probe120b-fullprefix-ref01` stopped by its own zero-max protocol and remains FAIL. For this new diagnostic reference only, the `run_bounded.py --allow-cgroup-max-reclaim` option permits max events but requires progress, no OOM/swap/allocation failure, observed `memory.peak<=memory.max`, headroom>=6 GiB, GPU<=7000 MiB, CPU<=95 C, GPU<=80 C, NVMe<=70 C, and a 17.5 GiB RSS guard. The production streamed side retains a 17 GiB RSS guard and disallows max events. Both runs require GPU/cgroup/thermal telemetry, local/hierarchical events, file/anon and PSI samples, first/last sample <=2 s from process boundaries, max gap3 s. A 7 s model-free monitor smoke after sensor preflight observed first sample0.066 s, end gap1.0 s, max gap1.08 s. No page-cache warmup of model weights occurs outside the cgroup; the checksum used O_DIRECT.

Execution order: 20B short smoke for the new probe/tool first (not 120B certification). Then one CPU0 plain `mmap` target reference for all three cases with the diagnostic no-prefetch flag and one CPU0 streamed target run with 24 slots/O_DIRECT; 1800 s timeout each. The comparison is a separate no-replace report and requires both source runs to finish cleanly. If reference fails by resource/timeout, stop this subprotocol, diagnose the cause, and use at most one further reference attempt with a distinct prospectively documented reason. A GPU8 plain reference with the same placement is attempted only after a capacity check shows a viable allocation; plain materialization of all GPU experts may make it infeasible. A stream24/stream32 comparison alone cannot replace independent plain/stream parity. If production placement cannot be matched, report CPU equivalence only and C2-B PARTIAL/NUMERIC_COVERAGE_BLOCKED; no robust-runtime promotion follows.

No performance gain claim from this instrumented diagnostic. Candidate and reference binary hashes are recorded at run time, with build identity and command in manifests. Raw `.f32`, logs and one-second samples are local and ignored; compact row hashes, comparison and coverage matrix are publishable as local commits. Tests at freeze: official tokenization, tool compilation (stream side), three monitor smokes, and model-free numeric mismatch gate; target teacher-forced decode NOT_RUN.

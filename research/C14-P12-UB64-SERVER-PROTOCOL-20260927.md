# C14 native P12/ub64 8K server resource protocol

- Objective/base: test whether native ub64 on P12 shortens a cold 513-ID prefill enough to finish with CPU thermal margin, using the original backend and weights. Base `aac280a50be730bb3be72b5d73c71c6214c70fd5`; measurement commit will contain this freeze. C11 P12/ub32 completed once at CPU95.0 C and 80.020 s backend prefill; C13 P12/ub32 repeated first request failed at CPU95.125 C. C10b P8/ub64 also failed CPU95.125 C, preserved.
- Hypothesis/alternative: C4 native ub64 reduced graph callbacks 1225→700 and a short no-preload prefill 44.625→40.775 s, so P12/ub64 might finish before CPU thermal saturation. The C4 workload differs; C10b shows ub64 alone did not rescue P8. CPU routed dot, I/O and remaining waves may dominate; ub64 changes shapes/arithmetic and requires its own numeric profile reference.
- Frozen variable: relative to C11 server argv, only `-ub 32→64`. P12 ngl12, slots32, preload ON, original backend/model, 8K full SWA, KV settings, thread counts, E18 and absolute guards remain. The same synthetic 78-ID/four-token forward and 513-ID/four-token cold input content and embedded tokenizer are used. Output IDs and routing are not compared cross-profile as pass/fail.
- Capacity: P12 expert pools unchanged at 25 CPU/11 CUDA layers ×32 slots×13,219,200 B. C11's 513-ID GPU peak was 5746 MiB; C10b P8 ub64 minus C9 P8 ub32 8K server GPU peak was +8 MiB, suggesting ~5754 MiB before P12-native64 workspace differences. This estimate is not admission. Bounded init-only (120 s), minimum forward (180 s), then 513-ID cold request (300 s), each fresh process and clean measurement commit. No concurrent 120B/reference.
- E18: systemd user scope memory.max18GiB/swap.max0; RSS≤16GiB, cgroup≤16.5GiB, GPU≤6500MiB, MemAvailable≥6GiB; CPU/GPU/NVMe≤95/80/70 C and start CPU≤55 C; telemetry ≤1 s/endpoints/mapped libraries/raw hashes required. Any guard/evidence failure ends the unit and is preserved without retry.
- Prospective investment rule: if the one 513-ID diagnostic completes with CPU peak ≤92 C and backend prefill ≤75 s, build native64 same-profile full-logit/36-layer reference before timing. Otherwise close this mechanism's diagnostic without numerical/timing promotion and return to the critical-path/thermal portfolio. These thresholds guide the next test and do not claim significance or M3. Default/usual server unchanged.

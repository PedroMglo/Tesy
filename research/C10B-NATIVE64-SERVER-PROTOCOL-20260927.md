# C10b native ub64 server admission protocol

- Objective: admit the original-backend P8 native ub64, preload-on 8K full-SWA server as a new numeric profile. Base commit `62b96563f66c20b9fe9276e4aeaa6845c92eed61`; measurement commit will be the commit containing this protocol. Source hypothesis and accounting are in `results/c10b-20260927T1520Z/`.
- Prior evidence: C8 P8 ub32 preload-on improved the frozen 496+32 probe T_work by 16.59% in three new paired confirmations. C9 ub32 server minimum forward passed E18, but first 513-ID cold prefill exceeded CPU 95 C. C10 ub64 was blocked by an additional 47 C start-temperature precondition before loading the model, with two no-model receipts preserved. C4's ub64 prefill/wave observation is diagnostic and had a different workload.
- Hypothesis: native ub64 may reduce prefill graph/wave overhead while retaining E18 resource margin. Strong alternative: CPU critical work or thermals dominate and the 513-ID server request still crosses 95 C. Numeric risk: ub64 is a different arithmetic profile; C4 cross-profile logits differed. No fidelity or timing promotion follows from resource admission.
- Variable: only server `-ub 32→64` relative to C9. Backend commit, binary, model, 8K/full SWA, P8 placement, preload, slots, threads, prompt cache policy, E18 and absolute guards are frozen in `init-protocol.json`, `forward-protocol.json`, `short513-protocol.json`. C10b changes C10's extra CPU start precondition from 47 C to 55 C prospectively; absolute guard remains 95 C.
- Sequence: bounded init-only (120 s), minimum synthetic 78-ID/four-output-token request (180 s), then one 513-ID/four-output-token synthetic cold request (300 s). A clean measurement commit precedes every unit. Stop on any guard, evidence or process failure; no replay within an identity. The server's official tokenizer records IDs before outputs. Raw stays local; compact receipts are committed after each unit.
- Evidence class: source/static accounting and model-free tests before execution; physical receipts if admitted. E18 systemd user scope, zero cgroup swap, RSS ≤16 GiB, cgroup ≤16.5 GiB, GPU ≤6500 MiB, MemAvailable ≥6 GiB, CPU/GPU/NVMe ≤95/80/70 C. Source monitor samples at ≤1 s and validates endpoints/identity. Precondition CPU ≤55 C at launch.
- Alternatives/decision: if ub64 resources fail, preserve the FAIL and switch to an independent model-free critical-path or residency bound. If it passes, ub64 remains a resource-admitted profile only; observer OFF/ON, canonical layer reference, timing and functional quality remain NOT_RUN. The default server is unchanged.

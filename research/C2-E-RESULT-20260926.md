# C2-E frozen twelve-task utility pilot

Decision: **UTILITY_OBSERVED_PILOT, SELECTIVE_FALLBACK_CANDIDATE**, subject to the C2-B target numerical coverage block. This is a practical, small-sample result for this artifact/backend/cap, not proof that larger models are generally superior or that the target runtime is numerically qualified for daily use.

The twelve synthetic evaluation tasks and gold/mutant-tested validators were frozen before either C2-E model response in `workloads/c2_tasks.json` (SHA-256 `11c09d2671adbea0214477a2bbb38e2a84a65dbfae1a01b7ce98123f8a74ab02`). The originally selected eight-task fallback was prospectively expanded to all twelve before answers, using C2-C's measured decode rate and remaining campaign budget. Both model runs used medium effort, temperature0/seed42, one attempt, max output2048, context4096, no prompt cache, full 18 GiB/zero-swap host envelope and the same semantic task prompts. Stock 20B GPU14 (`llama.cpp` SHA `4b1a27fa0eb875bbca4f6cfe936e3d65adc685c0`) ran first; target 120B GPU8/32 slots (streamed SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`) ran second, with one model process at a time. Model identities/hashes and library hashes are fixed in `workloads/c2e_eval12_{stock20,target32}_protocol.json` and the no-replace run manifests.

The official server template/tokenizer counted every prompt **before generation**, stored token-ID hashes, and matched every subsequent API prompt count. Stock prompts were 127–279 tokens, 2027 total; target prompts 113–265, 1859 total. Every prompt left the full 2048 output-token reserve under context4096. These short task prompts do not validate 4K context use. Both strict C2-A run gates passed all twelve IDs, API/backend counts and timings, 1 s telemetry coverage, PID/cgroup identity and final resource checks; both local publication manifests have status PASS. The `tools/c2_task_grade.py` validators executed code/SQL without network or credential mounts under bounded bubblewrap, with 16 gold examples passing and 16 deliberately wrong mutants failing before the model runs. A validator environment error would abort grading.

**Result:** target 12/12, stock 10/12; ten ties, two target-only wins, zero stock-only wins. Both target-only cases are specific: stock generated the full 2048-token cap entirely in reasoning, with no final content; target code-02 ended naturally at 1585 completion tokens and passed multiple isolated code assertions, and target plan-01 ended naturally at 1636 tokens with the exact validated schedule JSON. The target code solution and plan JSON were inspected after grading and matched the required interfaces/fields; no rubric or cap changed. A larger stock cap could change these outcomes and requires a separate prospective comparison. The old C1 ten-task result remains an 8/10 tie for both and is not reclassified.

The target's sum of request wall times was **11.478×** the stock's, despite fewer completion tokens. The two extra verifiable solutions cost 519.272 s and 462.543 s when run on the target, compared with 47.178 s and 51.428 s for the stock attempts that stopped without final answers. Failed stock attempts are included in total time. Per-task wall and token counts, finish reasons, outcome details and reasoning/final character counts are in the grade/comparison JSON. The nonstreamed task API did not expose per-token TTFT or a reasoning/final token split: both are **NOT_MEASURED** for this suite. C2-D separately measured first text/final latency for different frozen prompts. Sampled target process `read_bytes` increased by 4,441,687,187,456 B, stock by 11,539,320,832 B; this is process-accounted I/O, not exclusive physical NVMe traffic or bytes of encoded expert payload.

Resource/thermal and completeness checks: stock 256 samples, maximum gap 1.356 s and 0.654 s end gap; target 2862 samples, maximum gap 1.406 s and 0.167 s end gap. Minimum sampled host MemAvailable was 21.934 GB stock and 12.994 GB target, above the 6 GiB guard. Both processes stopped normally, released GPU/port and had zero swap/max/OOM/kill deltas at the final cgroup audit. The target's 50-minute run includes sustained thermal behavior under this task mix, but its 3.497 tok/s aggregate is not a prospectively frozen >=4 tok/s sustained gate. The different backend versions, placement and tokenization prohibit attributing outcome or timing differences solely to model size.

This is a twelve-case synthetic pilot, not a statistically powered estimate. The two exclusive wins motivate a selective fallback hypothesis when the fast 20B reaches cap with no final answer, but the 120B's first-final latency and 11.478× aggregate time rule out broad default use on these observations. More importantly, C2-B independent target numerical parity remains **NUMERIC_COVERAGE_BLOCKED/PARTIAL**; functional task passes cannot fill that gap. No optimization intervention or sampler/context/effort change was introduced in C2-E.

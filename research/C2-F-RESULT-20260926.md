# C2-F monitored local launcher and context/lifecycle diagnostic

Evidence class: **MEDIDO_NO_TARGET** for the tested 120B process. Source/backend pins are unchanged: `ggml-org/gpt-oss-120b-GGUF` MXFP4 revision `238abdd290bb874b90a5da1b4549881b7d05c091`, SHA-256 `582bd40f6886200101f4c4ed9f25f3fe80cc14c86e9e2b37746cd8904a0c622d`, streamed backend `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`. The launcher `tools/c2_launch_target.py` checked a clean backend worktree, frozen binary/library/configuration identities and a full read-only O_DIRECT GGUF SHA-256 before starting the server. Full-hash preflight took 48.895 s, outside the 1881.576 s measured server process. The server listened only on `127.0.0.1:18367`, with memory.max 18 GiB, memory.swap.max=0, RSS 17 GiB, GPU <=7000 MiB, MemAvailable >=6 GiB and CPU/GPU/NVMe guards 95/80/70 C. One server process handled all probes.

Tested launcher command (the run ID is reserved and must change on replay):

```sh
python3 tools/c2_launch_target.py --run-id c2d-target32-latency-server01
```

The server then handled three frozen latency requests and three synthetic multi-turn requests. `tools/c2_multiturn_probe.py --output results/c2f-target32-multiturn01.json` reported actual templated/API prompt counts **86, 663, 2150**, exactly equal in each turn and strictly increasing, with zero API cached prompt tokens. Completion counts were 78, 107, 66, all natural `stop`; the synthetic remembered key was correct all three times. Request walls were 49.988, 238.434 and 660.756 s. This validates a real three-turn context reaching 2150 prompt tokens with 256 output tokens reserved under context4096. It does **not** establish correctness at the full 4096 boundary or at 8192 and above. No context shift or truncation was reported in these requests.

`tools/c2_cancel_probe.py --output results/c2f-target32-cancel01.json` closed a streamed synthetic request after the first nonempty text, 2 chunks and 29.445 s. The server stderr records `cancel task, id_task = 514` and slot release. A following request completed normally after 37.671 s with final `12`, 80 prompt and 40 completion tokens, `finish_reason=stop`. This tests cancellation and subsequent service in this one-process scenario; it does not exhaustively test concurrent clients or every error path.

`tools/c2_stop_server.py c2d-target32-latency-server01 --model-path /home/pmglo/models/gpt-oss-120b-gguf/gpt-oss-120b-MXFP4.gguf` first passed `--dry-run` identity/cgroup verification, then stopped only the sampled server PID. The bounded monitor observed normal returncode 0, no stop reason, no swap or cgroup max/OOM/kill event, and whole-process peaks `memory.peak` 14,819,639,296 B, RSS 15,041,060,864 B, total GPU 3858 MiB and CPU/GPU/NVMe 91/61/59.85 C. The loopback listening port and GPU compute process list were empty after shutdown. Raw server/client output, stderr and samples remain local with no-replace IDs. Server manifest SHA-256 `900e822bbe3bc6ecadf3bbdffc75285aa0048b4b24e208523c22f4534b15e7b6`, multi-turn SHA-256 `6ae24e1834a85fe832409eed3543cc58de03d426792a565ffaeeb57f5f090eda`, cancellation SHA-256 `f6ed1815b2bcfc71e779cfc6f766122457fb9e4bf4287cd239e46444d39f3d37`.

Decision: keep the launcher as a **tested diagnostic local service** for the frozen GPU8/32-slot profile. It is not promoted to robust daily use because C2-B has only partial target numerical coverage, the short-prompt first-final latency is 74.506 s, the full 4K context boundary was not tested, and longer term multi-client reliability remains unknown. A fresh run ID is required on every replay; never overwrite an existing result.

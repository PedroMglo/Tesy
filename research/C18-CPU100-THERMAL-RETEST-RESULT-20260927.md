# C18 CPU100 retest: four cold513 arms complete

- Objective/base: retest only the P8/P12 cold 513-ID server arms stopped or left NOT_RUN by the earlier experimental CPU95 guard. Measurement base `01e64cc5ac1498574258790abd4afec029124e95`; original model SHA, backend binary/libraries, server argv, IDs, 8K/full-SWA/ub32/slots32/preload ON and E18 zero-swap scope were frozen against C17. Evidence class: physical host, fresh processes, completion-fenced server responses and sampled resources. Six old CPU95 stops stay in their original files; C18 identifies them as `FAIL_PROTOCOL_THERMAL_GUARD` without replacing raw or decisions.
- Alternative considered: cold513 might complete between 95 and 100 °C, or explicit thermal mitigation/clocks might invalidate it. CPU100 was sourced from AMD's HX 370 Tjmax specification before measurements. C18 captured warning samples, effective CPU clocks, package RAPL interval power and ACPI Processor cooling states; an AMD direct hardware thermal flag was unavailable. No power/fan limit was changed.
- Result: all four new 513+4 requests passed raw/hash/mapping/cgroup/server gates. Order P8→P12 then P12→P8. Request times: P8 90.022/P12 80.250 s, then P12 80.801/P8 89.622 s. Paired gains in request time: 10.8557% and 9.8429%; median of paired gains 10.3493%. These are descriptive two-pair results, not a p95 or general speed claim. Full returned message SHA repeated within P8 and P12; full 8K server logits remain NOT_RUN.
- Resources: CPU peaks 95.125/95.125/95.0/95.125 °C; 17/12/6/14 warning samples, ACPI Processor cooling state 0, no CPU100, no swap/OOM/cgroup cap event. GPU total stayed below 5.8 GiB, GPU temperature below 80 °C and NVMe below 70 °C. The P12 inverted-pair admission took 848.6 s because a competing graphical monitor raised idle CPU temperature; the owner authorized termination of only that application and a new continuous 300 s idle segment passed. Ambient temperature and causal attribution of cooling remain UNKNOWN.
- Decision: `THERMAL_RETTEST_PASS` for the tested P8/P12 cold513 profile under the prospective CPU100 policy. The earlier CPU95 stop was a protocol limit for this workload; it does not establish session usability. Cold prefill ~79–89 s is still far above the proposed 30 s M4 cold512 goal. M3/M4, exact-prefix, functional tasks, sustained regime and C15 build/timing remain NOT_RUN; default unchanged.
- Next discriminating gate: C19 new-identity P12 exact-prefix ON 512+128 synthetic server mechanism screen, reusing C13 frozen input and exact tokenization/cache accounting under CPU100/E18 and matched idle admission. If reuse is observed, measure the incremental session effect with controls before a use-profile claim. C15 remains source-only while this cheaper product-path question is unresolved.

# M1 synthetic direct-read EIO: fail closed on 20B initialization

Objective and fixed criteria: `research/M1-IO-FAULT-PREFLIGHT-20260926.md`, freeze commit `33c4804`; base candidate SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, unmodified. This is a synthetic one-shot read-error test on the verified local 20B GGUF, not a 120B routed-output or throughput result. The reproducible injector source is `tools/fault_pread.c`; `tools/run_20b_read_fault.sh` compiles it into an untracked local shared object and invokes the existing eight-token GPU8 smoke under an enforced 9 GiB/zero-swap cgroup, RSS8.5 GiB/GPU7000 MiB/MemAvailable6 GiB watchdog and 180-second timeout. No model bytes were written or copied. The run manifest, assessment with injector/log hashes and raw local logs are `results/fault20b-direct-read01*`.

The injector sentinel `TESY_FAULT_PREAD_DIRECT_EIO` appeared **once** in stderr. The next backend message was `MoE expert streaming: expert load failed (I/O error)` at the remap wait. The process aborted with return code -6 after 5.239 s, in the model initialization/warmup path before a user answer was identified. There was no watchdog timeout, no swap, no cgroup max/OOM event; sampled peak cgroup memory was 3,415,351,296 bytes and total GPU used 2356 MiB. The backend did not silently use a partial expert or report a successful response. A debugger backtrace was printed by the backend's abort handler; it does not change this result.

Decision: the predeclared **fail-closed** criterion passes for this one injected O_DIRECT `EIO`. This does not prove propagation of partial short reads, EOF on another slab, failed GPU upload, slot reuse while compute is in flight, queue cancellation, or target 120B decode behavior. No source optimization or correctness threshold was changed. The fault library is a build product and remains untracked; its SHA-256 is in the assessment. The original 20B and 120B functional results remain separate.

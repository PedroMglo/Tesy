Eight plain GPU layers would require 8 × 128 × 13,219,200 = 13,536,460,800 bytes of expert weights alone, above the 8 GiB physical VRAM and the 7000 MiB campaign guard. A full plain GPU8 reference is therefore not a viable same-placement control in this envelope. A differential control with existing kernels would be narrower than full-model GPU8 parity and has not been run. CPU0 streamed versus plain parity beyond the historical four-token row also remains NOT_RUN because both full reference attempts failed.

## Fail-closed read and lifetime evidence

The test-only interposer defers its one O_DIRECT fault until after the 20B context loads. It never writes weights. EIO, 4096-byte short read, and EOF each emitted exactly one arm and injection marker, then the backend's `expert load failed (I/O error)` abort with return code -6 and zero float32 rows. The 200 ms delay case completed all 30 rows and matched independent plain CPU0 bitwise; the log records 1512 misses (688 cold), 824 reloads and 552 waves under 16 slots. The injector's local disposable-file selftest also passed all four modes. This verifies failure propagation and one delayed read under churn on 20B, not GPU upload failure or all in-flight eviction schedules.

Source audit at backend `1248fd8`: `llama_moe_stream_pread` rejects short/EOF/EIO; workers mark slots RESIDENT only after all tensor reads and uploads return; a global `load_failed` wakes waiting remaps, which abort before emitting slot IDs. Victim selection skips LOADING slots, queued work checks slot generation/expert/state before claiming, and the CUDA `set_tensor` implementation synchronizes its per-thread stream before returning. These are implementation observations, not a substitute for a deterministic stale-publication/in-flight eviction test. That coverage remains open. No backend patch was made.

**C2-B decision: NUMERIC_COVERAGE_BLOCKED/PARTIAL.** The target still runs and generated the smoke, but robust exactness of the production placement is unqualified. C2-C may collect a bounded performance diagnostic under its frozen protocol; such a run cannot alone promote a daily-use profile or justify a new optimization. C2-E can still be a labeled pilot of observed outputs, with this correctness limit attached.

**MEDIDO_NO_TARGET, unchanged GPU8/32slot/ub32/no-preload boundary.** The official server template/tokenizer regenerated the exact C2-D prompt lengths 113/496/1522 from synthetic `workloads/c2_latency_prompts.json` (SHA-256 `0190f1cef2228a0937005a4c8a2bf790b3e7e49bce9782c52d0f857a8baf20c0`). A prefill-only native probe used the same 256 batch/32 microbatch, context4096, CPU8/I/O4, direct expert I/O and a single process in short→medium→long order, clearing KV between cases but retaining expert cache. The trace matched exactly three expert read calls and three cache tensor writes per backend miss in each of nine prompt chunks. All three final 201,088-float32 logit vectors and all access counters were bitwise/integers equal with tracing OFF/ON. The source analyzer first rejected a valid chunk with zero reads in one layer; its FAIL output is retained as `...account.json`. The corrected `...account-v2.json` admits an explicitly zero-I/O layer only when global miss/read/upload accounting matches, and passed. The observed trace-versus-control wall differences were -0.52%, +0.97% and +0.07% over the three prompts; a separate short smoke was +4.14%. These ordered single pairs do not isolate instrumentation overhead from cache/thermal dispersion. Trace timings remain diagnostic.

`pread` returned bytes are application read payload, not device-exclusive NVMe traffic; requested bytes include O_DIRECT alignment. Upload bytes are calls to `ggml_backend_tensor_set`, including CPU cache copies, not PCIe traffic. Of returned bytes, CPU-layer tensors accounted for 47.567/143.072/388.862 GB and GPU-layer tensors for 9.646/20.866/44.100 GB (short/medium/long). Backend wave-wait counters accumulate 27.539/78.520/211.790 s; their ratio to untraced prefill is about 64/52/49%, but this is **not** an exclusive wall-time breakdown. CPU compute, GPU compute and overlap were not separately timed with events, so their avoidable shares remain UNKNOWN. The per-layer/chunk counts and source hashes are in `results/c3-p1-prefill-all-trace01-account-v2.json` and `results/c3-p1-prefill-all-pair01.json`; case totals are `results/c3-p1-summary01.json`. Raw trace and logit arrays stay local.

The untraced run completed in 632.762 s, cgroup memory peak 14,697,431,040 B, sampled GPU peak 3898 MiB, zero swap/max/OOM/kill; max CPU/GPU/NVMe 91.75/58/55.85 C. The traced run completed in 634.766 s, cgroup peak 14,830,497,792 B, sampled GPU 3898 MiB, zero swap/max/OOM/kill; max 92.125/59/57.85 C. Both are below frozen guards. Host page cache was uncontrolled, while sampled target descriptors were O_DIRECT. C2-D's previously measured server prefill 41.353/146.961/447.076 s is close but a separate process/protocol, not an A/B arm.

**Decision before intervention:** repeated encoded expert reads and blocking wave wait are material in every prompt. Test the pinned backend's already implemented next-wave preload first, changing only the presence of `LLAMA_MOE_STREAM_NO_PRELOAD`. The next wave's IDs come from the current real router, so this is a scheduling change, not altered routing. Requalify bytes/FFN/logits, then compare full-model prefill and decode under the same bounds. The prospective engineering goal remains >=25% prefill reduction on both 496/1522 prompts with decode >=3 tok/s and no correctness/resource regression; a single screening run will not be promoted as reproducible gain. Optimization interventions consumed so far: 0/4.

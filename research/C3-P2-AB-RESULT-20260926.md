# C3 P2 preload: scoped correctness and paired prefill result

**MEDIDO_NO_TARGET, SHORT_ONLY pending sustained server.** Lab base for the preload intervention `5f47c6d`; protocol and binary bridge in `C3-P2-PRELOAD-PROTOCOL-20260926.md`. The sole runtime variable is absence versus presence of `LLAMA_MOE_STREAM_NO_PRELOAD`; GPU8/32 slots/ubatch32/context4096, original backend and artifact are unchanged. This consumes intervention 1/4. C2's historical global `CORRECTNESS_BLOCKED` remains untouched.

The first preload capture comparison failed because the capture binary had changed since R2; its `FAIL_EVIDENCE` output remains. A new no-preload binary bridge matched the R2 independently referenced captures, then preload matched the bridge. For each of the two frozen target cases, **1512/1512** logical pre-FFN input/router/FFN tensor pairs and seven full 201,088-float32 logit vectors were bitwise equal; direct canonical slot-byte checks covered CPU0/GPU35. The actual preload run and control used identical capture binary and backend libraries. This is conditional differential coverage, not full plain-model parity or arbitrary-input certification.

The first A/B series failed its telemetry gate after one pair: the candidate's last sample lacked VmRSS/VmSwap during process exit. The analyzer retained `FAIL_EVIDENCE`, and the second-pair ON arm was interrupted without promotion. A model-free smoke, a failed short model smoke and a successful new short model smoke document two repair cycles of the watchdog. The successful runner requires full process fields or proves actual child exit within 0.2 s, samples about every 0.5 s, and produced 80 complete samples with 0.501 s end gap and bitwise-equal short logits. The failed runs are not used as A/B data.

The replacement `c3-p2b-ab` completed all six fixed arms, alternating OFF→ON / ON→OFF / OFF→ON. Every paired final prompt logit vector was bitwise equal; all guards, sample coverage, zero swap/max/OOM/kill event deltas and no-replace manifests passed. The prospective smaller-gain criterion passes at 496 and 1522: all three candidate arms are faster, and each median gain exceeds the observed within-arm range. The prospectively proposed **>=25% prefill reduction goal fails at both sizes**. This result does not measure server TTFT or answer completion. The full A/B data/gate/source hashes are in `results/c3-p2b-ab-summary01.json` and three `c3-p2b-ab-p*-comparison01.json` files; raw logits, counters, samples and manifests stay local.

Across every replacement arm, backend misses were 49,436 OFF versus 12,299 ON plus 29,647 preload issues. At 13,219,200 encoded bytes per expert, requested load payload is 653.504 GB OFF versus 554.493 GB ON, a **99.012 GB reduction** in this workload. These are derived from backend load counts; they are not physical NVMe bytes. Process `read_bytes` sampled deltas were 655.935–655.973 GB OFF and 556.762–557.120 GB ON, consistent with fewer loads but not exclusive device traffic. Cumulative backend wave wait was 321–323 s OFF versus 202–203 s ON; it is not an exclusive wall-time component. The source issues preloads only for experts in the real router's next wave, but whether every issued preload completed before demand and how much transfer overlapped compute were not separately measured. `ready on arrival` counts all resident hits and is **not** a useful-prefetch counter; wasted bytes remain UNKNOWN rather than zero.

The largest cgroup `memory.peak` was 15,043,342,336 B, sampled GPU peak 3909 MiB, CPU max93.75 C, GPU max62 C and NVMe max59.85 C across six runs. No thermal/guard stop occurred. The narrower performance result justifies a new, separately frozen 20-request sustained server gate with decode>=3 tok/s and exact historical-output comparison. Until that gate passes, the default remains the C2 no-preload sustained profile.

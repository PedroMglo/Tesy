# M6 paired held-out tasks: no larger-model advantage observed

Objective and frozen protocol: `research/M6-PREFLIGHT-20260926.md`, `workloads/task_eval.jsonl` (ten held-out public synthetic tasks, two separate tune tasks), frozen before target answers. Lab base commit at freeze `6ccd72a`. Evidence class: measured one-attempt paired functional evaluation on the physical laptop, with fixed validators and documented manual exact-criterion judgments. Full responses, commands, binary hashes, resource samples and stop conditions are in `results/task20b-stock-eval02.json`, `results/task120b-stream24-eval01.json` and the corresponding judgment/analysis JSON files. `results/m6-paired-summary.json` joins the cases.

The target took **19.573 times** the summed request wall time on the matched task texts. The different prompt token totals reflect different model/tokenizer/template behavior. The configurations were the best observed stock 20B placement (GPU14, stock SHA `4b1a27fa0eb875bbca4f6cfe936e3d65adc685c0`) and the validated 120B stream (GPU8, 24 slots, candidate SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`). Their GGUF SHA-256 hashes are `52f57ab7d3df3ba9173827c1c6832e73375553a846f3e32b49f1ae2daad688d4` and `582bd40f6886200101f4c4ed9f25f3fe80cc14c86e9e2b37746cd8904a0c622d`, respectively. Both used context4096, one sequence, batch256/microbatch32, medium reasoning, greedy seed42, no prefix-cache reuse, max512 output and one attempt under the same enforced 18 GiB/zero-swap host cap. This is a practical comparison, not an isolated effect of parameter count.

Both passed `eval-code-02`, two SQL, two JSON extraction, two quantitative and `eval-plan-02`. Both failed `eval-code-01` and `eval-plan-01`. The 20B used all 512 tokens on each failed case without final content. The 120B generated final code for code-01, but its `start <= previous_end + 1` rule merged adjacent intervals contrary to a listed assertion; the local isolated assertion failed. Its plan-01 answer exhausted 512 tokens in a task/duration table before supplying a valid start/end schedule. Other code and SQL passes are limited to the fixed public assertions/fixtures. Exact quantitative/planning adjudications are archived in the judgment JSON files; no ambiguous case was silently counted as a pass. Initial stock grading incorrectly rejected two Markdown-fenced JSON payloads; the original failed grading report remains, and the parser-only repair was applied to both saved responses without changing criteria or generation.

Separate simple streamed smokes observed first received text at 0.974 s for stock and 35.113 s for target; first final-content chunks at 1.573 and 50.043 s. These are chunk-arrival latencies for that smoke, not task medians or per-token p50/p95. Stock max sampled CPU Tctl/NVMe/GPU temperatures were 86.875/47.85/67 C over its short run; target maxima 88.125/61.85/58 C over 22m22s. The sustained target thermal windows and no late decode collapse are in the M5 server report. The target's ~2.044 TB process read counter is not exclusive storage-device traffic.

Decision: **M6_LARGER_MODEL_TASK_ADVANTAGE not demonstrated** on this small fixed suite. The observed score tied 8/10 with no paired win or regression, while the target incurred much longer completion time. This does not prove general equality of model quality or statistical significance. M4 and the separately qualified M5 remain demonstrated; M6 was evaluated and was negative. No backend change was retained or reverted for M6. A next discriminating quality experiment would require a prospectively fixed larger authorized suite with tasks where model scale could matter, keeping output budgets and validation policy fixed before execution; it is not justified to assert an advantage from these ten tasks.

# M6 stock 20B held-out baseline

Objective and frozen workload: `research/M6-PREFLIGHT-20260926.md`, `workloads/task_eval.jsonl` (ten held-out cases, two separate tune cases). Lab base before M6 `eaeae2d`. Independent stock backend SHA `4b1a27fa0eb875bbca4f6cfe936e3d65adc685c0`, verified 20B MXFP4 GGUF SHA `52f57ab7d3df3ba9173827c1c6832e73375553a846f3e32b49f1ae2daad688d4`, GPU14, direct loader, lazy mode off, context4096, one sequence, batch256/microbatch32, eight CPU threads, embedded template with explicit medium reasoning, greedy seed42, no prompt cache, max512 completion tokens and one attempt per task. Exact binary/library hashes, command, output and resource samples are in `results/task20b-stock-tune01.json` and `results/task20b-stock-eval02.json`; public responses are in the latter. No remote service or private data was used.

Measured held-out score: **8/10 pass, 2/10 fail** against the predeclared validators. Passing: `eval-code-02`, both SQL, both JSON extraction, both quantitative and `eval-plan-02`. Failing: `eval-code-01` and `eval-plan-01` each consumed 512 completion tokens with `finish_reason=length` and no final answer. The automatic report `results/task20b-stock-eval02-grade02.json` includes sandboxed Python/SQLite checks and parsed JSON; the exact-criterion manual adjudication of three numeric/planning cases is in `results/task20b-stock-eval02-judgment.json`. Code tests cover the listed assertions only; a pass is not a broad software-quality claim. An earlier `grade.json` false-failed the two correct fenced JSON outputs due a parser omission; that diagnostic remains intact, and the same repaired parser is frozen for the target. A prior `eval01` attempt failed before model launch due a `TIME_WAIT` port-guard bug, separately retained in `DECISIONS.md`.

The ten API requests took 65.644 s summed wall time, generated 2,421 completion tokens from 1,234 prompt tokens, and the whole fresh-process run took 75.241 s including model load and first-text smoke. Server ready at 7.486 s; first text chunk for the separate simple smoke arrived 0.974 s after request, first final-content chunk at 1.573 s. These are client-observed chunk arrivals, not per-token intervals. Peak cgroup 6,658,342,912 bytes and GPU used 6,578 MiB; zero swap/OOM/limit events. Sampled max CPU Tctl 86.875 C, NVMe 47.85 C, NVIDIA GPU 67 C. No server remained after the run.

Alternative and decision: the stock GPU14 placement was the fastest stock 20B configuration observed in M0/M1; the M6 server uses that placement under a common 18 GiB cap. Keep this 8/10 result fixed before target evaluation. Different model/tokenizer/template/backend identities and placements must be reported alongside any target advantage or latency penalty. Next gate: target 120B on the same public task texts and one-attempt/medium-effort policy, then paired success and time comparison. Target tune had an initial pre-load CLI flag incompatibility; the model's verified template default and supported template kwarg both specify medium, and `task120b-stream24-tune02` then completed.

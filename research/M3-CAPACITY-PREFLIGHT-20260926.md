# M3 prospective cache-capacity experiment

Objective: determine whether increasing the existing streaming cache from 16 to 24 expert slots per layer reduces demand loads and improves exact 120B decode under the same bounds. Evidence before change: `research/M2-RESULT-20260926.md` measured 30,063 misses, 397.409 GB encoded miss payload, and 124.474 s remap stall in a two-request 16-slot run. A larger cache may help, but a high hit rate alone cannot establish throughput gain. Base lab commit `364ecf4`; source candidate remains `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`.

Only experimental variable: `--moe-stream-cache 24s` instead of `16s`, using the same compiled source, GGUF SHA, eight GPU layers, O_DIRECT, no preload/repack, CPU threads, context 4096, batch 256/microbatch 32, greedy sampler and two-prompt workload. The 24-slot encoded expert pool would be 11,421,388,800 bytes total, with 8,883,302,400 bytes on 28 CPU layers and 2,538,086,400 bytes on eight GPU layers. This adds 2,961,100,800 host and 846,028,800 GPU bytes nominally. Existing 18 GiB cgroup, zero swap, 17 GiB RSS watchdog, 7,000 MiB GPU cap and 6 GiB MemAvailable floor stay fixed. Actual startup/prefill/decode peaks and OOM events decide safety.

Primary A/B metrics: each request's measured decode tokens/s and whole-run decode tokens/s; secondary: per-process read bytes, misses/hits/stalls when a like-for-like diagnostic run is possible, prefill, end-to-end time, and resource peaks. A retained throughput gain needs repeated alternating same-binary A/B with stable correctness and resources; one run is exploratory. Forbidden regression: different prefix logits, different greedy output tokens/text, swap/OOM/resource cap, partial expert reads, or routing changes. A mismatch stops promotion regardless of speed. Comparison coverage is one fixed four-token CPU prefix against saved reference plus two free-generation greedy texts; this does not certify every routed path. We will first run the prefix probe, then a full 24-slot candidate. Repeat A/B only if first 24-slot run passes. Revert by selecting 16 slots, without touching source or previous results.

Alternative interventions considered: extra I/O threads, policy replacement, RAM tier, O_DIRECT removal, GPU layer shift, prefetch and speculative decoding. All change more than one cost mechanism or need finer accounting. This slot change is the least invasive test of the measured capacity pressure. It is optimization/configuration intervention 3 of six cumulative, irrespective of outcome. No target threshold changes: sustained >=2 decode tok/s remains the primary performance objective.

Tests: NOT_RUN at freeze. Output roots `results/probe120b-prefix4-stream24-01*` and `results/target120b-gpu8-two-turns-slot24-01*`; local publication only. Stop on any watchdog, swap/OOM, incomplete provenance, numerical mismatch, or model error. Success at this experiment does not by itself establish M5 sustained or task benefit.

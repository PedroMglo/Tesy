## Measured

- Under 16 slots/layer, 10,178 remap calls made 54,134 expert accesses across calls: 24,071 ready/in-flight hits, 30,063 demand misses, 3,943 first-ever cold misses; aggregate hit rate 44.47%. The 54,134 accesses are not unique `(layer, expert)` pairs. There was no speculative preload. Existing `n_preload_ready=2647` naming also counts already-resident wave experts, so it is not evidence of prefetch. The implementation has no independently measured dynamic RAM cache tier; these are cache hits in the selected device/CPU buffers, aggregated across placements and phases.
- All three encoded expert weight slices together are 13,219,200 bytes per miss, measured from GGUF tensor dimensions/types. `30,063 x 13,219,200 = 397,408,809,600` encoded payload bytes requested by demand loads, barring a failed/duplicate load. The last sampled process `/proc/PID/io:read_bytes` was 397,482,385,408 bytes, 73,575,808 bytes above that payload. O_DIRECT model FD was observed throughout decoding. The close match supports that expert loads dominate this process counter in this run. It does not turn `read_bytes` into exclusive physical NVMe traffic: btrfs/filesystem behavior and concurrent device traffic were not independently measured. O_DIRECT alignment, nonexpert loader reads and 1-second sampling contribute to the difference. `rchar` and returned syscall bytes are not separately instrumented per slab.
- Sampling near logged phase boundaries gives approximate process read deltas: first decode from ~52.15 s to 123.64 s, 126.94 GB / 158 = ~803 MB per committed token; second decode from ~234.96 s to 297.25 s, 107.61 GB / 114 = ~944 MB per committed token. Boundary error is about a second of runtime I/O (roughly 2 GB), so these are estimates, not exact per-phase payload. The second request's distinct route/cache behavior and context state may explain higher bytes/token; no per-layer trace was taken to isolate cause.
- Existing wait counters reported 124.474 s in remap handling and 72.767 s in wave handling across the run. These are measured blocking intervals of different callbacks; no claim that their sum is an exclusive fraction of wall time or that every wait is physical disk latency. Total run 298.251 s; prefill 84/48.930 s then 201/111.655 s; decode 158/71.143 s = 2.221 tok/s then 114/62.310 s = 1.830 tok/s. First run's second decode was 1.998 tok/s. The difference is unexplained run-to-run dispersion; the output texts remained byte-identical. Temperatures stayed within 57 C sampled GPU and memory/cgroup limits had zero swap/max/OOM events.

## Interpretation and uncertainty

Source audit: misses load the required original expert slabs, and the router IDs are remapped to slots without changing top-4; preload is disabled. This run cannot distinguish GPU hits from CPU hits, conditional RAM hits from storage misses, physical NVMe bytes, H2D bytes, evictions, compute versus transfer overlap, or ready versus in-flight hits in the generic counter. The cache hit rate is an observation under the current policy, not a lower bound on unavoidable misses. M2 is **partial** against the full requested tier accounting; it is sufficient to motivate a bounded capacity A/B because the measured miss payload and wait are large.

Alternative interventions considered: adding I/O threads, new RAM tier, O_DIRECT replacement, GPU kernels, or prefetch would change more mechanisms without an exclusive path breakdown. The least invasive discriminating test is 16 versus 24 slots per layer with the same policy, model, kernels, GPU placement, context and workload. This adds 3,807,129,600 bytes of nominal encoded cache across host/GPU, of which 2,961,100,800 bytes are on 28 CPU layers and 846,028,800 bytes on 8 GPU layers. Actual peaks must be measured; nominal allocations are not a resource proof. No optimization code has been retained yet. Next gate: freeze a 24-slot test, verify target prefix logits and exact generated texts, then alternate repeated full-model A/B if the first candidate run stays within limits.

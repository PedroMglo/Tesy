# NVMe direto para os slots CUDA do R0

**NO_GO para GPUDirect Storage nativo neste portátil e nesta colocação.** A matriz da NVIDIA, revista em 17 de novembro de 2026 e consultada a 25, admite GPUs Data Center e Quadro desktop em modo GDS. Para a GeForce RTX 4060 Laptop GPU indica apenas compatibilidade. A matriz de filesystems também classifica Btrfs como compatibilidade. Nesse modo cuFile pode fazer I/O POSIX para memória host e copiar os dados para a GPU. Uma leitura bem-sucedida pela API não provaria DMA direto para VRAM. [Matriz de GPUs](https://docs.nvidia.com/gpudirect-storage/release-notes/support-matrix.html) · [Matriz de filesystems](https://docs.nvidia.com/gpudirect-storage/release-notes/filesystem-classification-matrix.html) · [Semântica de compatibilidade cuFile](https://docs.nvidia.com/gpudirect-storage/api-reference-guide/usage.html)

**Observação passiva, 25 de novembro.** O GGUF canónico reside em Btrfs no NVMe interno. O módulo NVIDIA open é 620.70.06. O linker encontra libcufile 1.18.1 no CUDA 13.3. A documentação de versão regista o suporte Btrfs pelo caminho de compatibilidade desde 1.17. O kernel Fedora 7.3.4 tem PCI_P2PDMA e ZONE_DEVICE ativos. O módulo nvidia-fs está ausente para este kernel. Existe também uma implementação de P2PDMA por NVMe no kernel upstream que pode dispensar esse módulo. O sysfs mostra o NVMe e a GPU em portas diferentes da mesma raiz PCI. A capacidade de transação P2P efetiva deste par permanece **DESCONHECIDA**. Foram consultados apenas nomes e metadados de montagem, módulos, bibliotecas, GPU e dispositivos PCI; zero chamadas CUDA/cuFile, aberturas de pesos ou alterações de sistema. [Notas de versão](https://docs.nvidia.com/gpudirect-storage/release-notes/new-features-and-changes.html) · [Arquitetura de I/O no kernel](https://docs.nvidia.com/gpudirect-storage/overview-guide/software-architecture.html)

**Caminho atual.** O worker C291 lê três regiões do GGUF ou o prefixo de pesos de um pack C290 para staging host. Cada tensor recebe os bytes no slot reservado por `ggml_backend_tensor_set`. Para as 11 camadas CUDA, `ggml_backend_cuda_buffer_set_tensor` em `ggml/src/ggml-cuda/ggml-cuda.cu:714–720` do pin C269 `d0ebfbcc` usa `cudaMemcpyAsync` host→device e sincroniza a stream. A fonte tem SHA-256 `0de01a8cb0502a7eea43b130504dcfeebb6fbf9dce31c57f884337419b7071d5`. A escrita direta na arena **CPU** tem uma hipótese e um gate próprios.

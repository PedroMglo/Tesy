# Build stock independente, CUDA SM89

Congelado em 24 de novembro de 2026 antes do build. A fixture ClassLRU admite testar o caminho stock, mas o binário histórico identificado tem outro pin. Pergunta desta unidade: conseguimos produzir um servidor independente e confirmar a sua interface compilada para o envelope com mmap e cache de experts?

Usar apenas o Git local de llama.cpp, no commit `e95426f16982054c379ca7bdc8186996dd22f0fe`, árvore `3c5105435231a5095af520b352396d526d483dab`. Fazer clone local separado e detached nesta árvore. Sem alterações a fontes, builds históricos ou host. CMake Release, Ninja, gcc-15, g++-15, nvcc do CUDA 13.3, CUDA SM89 real e bibliotecas partilhadas. Compilar apenas o alvo llama-server, com suporte Flash Attention f16/f16 para o KV declarado, sem UI online, NCCL, HTTPS, ccache, testes, downloads, pesos ou forward. O modo sem Web UI conserva a API local. Executar após o sinal de fim do link C294.

Orçamento de execução de 1200 s, 6 GiB para o cgroup próprio, swap zero, até 4 GiB de novos ficheiros incluindo checkout, build, logs e temporários. Congelar até cinco jobs simultâneos. Se o preflight se encontrar com alimentação AC desligada, menos de 8 GiB disponíveis no host, menos de 4 GiB no destino, ou Tctl inicial ≥85 °C, adiar; durante a execução parar se AC desligar ou Tctl atingir 95 °C. Guardar picos observados, eventos do cgroup, orçamento de tempo, ferramentas e hashes. Uma falha preserva o destino local. Publicar recibos compactos sem dados do host identificativos.

PASS requer HEAD e tree exatos e limpos antes/depois, saída de `--version` com o prefixo do pin, opções do comando congelado em `--help`, ELF CUDA contendo código SM89, e dependências llama/ggml a resolver para o próprio build. Para verificar o binário sem carregar um modelo, estes dois comandos terão `CUDA_VISIBLE_DEVICES` vazio. Não estimar exatidão, custo por token, VRAM de um contexto real ou prontidão do 120B com este gate. Uma carga física do GGUF USB precisa de uma unidade e janela independentes.

# Que parte do orçamento pode vir de waves CPU sem um único rank ativo?

A parte 198 localizou 2,236 e 2,468 s entre waves da mesma camada CPU. O C291 já recebe TESY_CPU_WAVE_SKIP_PARKED=1. O novo mecanismo em estudo evitaria trabalho de grafo que ainda se faz depois de uma wave completamente vazia. A parte 122 mediu os 24 nós MMID numa só tile residente. Antes de alterar kernels ou executar outro pedido com pesos, testar se no nominal de 153 existe tempo suficiente no local onde a transformação atuaria.

Usar os mesmos P97 e P106, apenas os intervalos das duas chamadas externas originais. Em cada tile e camada reabrir os ranks do target e o conjunto de demandas por wave. Provar que cada expert de cada rank pertence a exatamente uma wave e reconciliar o total de ranks e reservas. Classificar uma wave como vazia se nenhum rank tem demanda nela. Verificar que essas waves formam um sufixo, sem reservas, e que a classe CPU ou CUDA corresponde ao mapeamento pinado. Para um trabalho bem-sucedido medir da saída do callback ao próximo início de callback, ou até ao retorno da mesma chamada. Atribuir a lacuna inteira à wave anterior, incluindo transições entre camadas ou tiles. Publicar separadamente CPU e CUDA, vazias e ativas, nas duas chamadas. Conservar entrada e soma. Uma duração assim atribuída é um teto favorável à eliminação localizada mesmo que o intervalo tenha outro trabalho. Nada pode ser creditado pela simples eliminação dos callbacks pois a parte 198 já concedeu todo o remap no prefill.

Cobrar apenas uma vez cada nanossegundo. Comparar a eliminação completa de todas as lacunas CPU vazias com o défice de cada journal e de cada cenário da parte 198. Fazer o mesmo concedendo os dois dispositivos como sensibilidade independente. Publicar a fração da lacuna necessária quando couber e a diferença em segundos quando não couber. Dar o saldo também para o caminho retrospetivo específico da parte 197. Se nenhum trace tiver margem no cenário mais favorável, NO_GO para juntar só esta mudança. Uma divergência entre os dois exige INCONCLUSIVE. Margem nos dois só admite uma fixture exata do custo marginal do caminho vazio, com o mesmo serviço, entradas, máscaras e reduções, sem nova campanha 120B nesta unidade. O critério dos 6 tok/s e as proteções M3/M4 seguem aplicáveis à futura receita.

Esperas que se propaguem além do callback seguinte, preços diferentes e um operador que acelere também as waves ativas correspondem a outras hipóteses. Validar com uma fixture de duas waves, ranks repetidos, wave vazia seguida de retorno e recusa de duplicação de proprietário. Reabrir a parte 198 e a origem dos ranks nos arquivos com hashes verificados. Duas reproduções em pastas novas, limite de 90 s, 768 MiB, zero swap, GPU e pesos.

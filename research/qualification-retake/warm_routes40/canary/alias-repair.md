# Reabertura após o alias no grafo real

OFF R1 terminou `C109_FAIL invalid target topk name`; ON ficou NOT_RUN. O erro aconteceu no reconhecimento de nós do novo observador. O binário e os dados R1 ficam associados ao commit 1670fb44e9e012b3a387b753b306a7e6650ecb09. O stderr R1 não publicou o nome concreto. No pin C269, `ggml_cont` conserva o nome de origem e acrescenta ` (cont)`; `ggml_reshape` também produz um nome derivado. O planeador real C294 cria `ggml_cont(selected_experts)` nas vias de uma e de várias waves. Um nó secundário com o nome completo `ffn_moe_topk-0 (cont)` é portanto um contraexemplo concreto ao parser de R1. O antigo grafo de fixture terminava no nó canónico e não exercitava o consumidor contíguo.

O ensaio sem pesos R2 passa o top-k original por `ggml_cont` no escalonador GGML CPU e verifica o nome que o próprio GGML produziu. Compila a fixture contra o header R1 selado para reproduzir a exceção antes de aceitar o reparo. O novo parser só aceita o nome canónico completo do layer; os derivados ficam fora. Remover ou mascarar o nó canónico tem de falhar na ordem completa de camadas. Mutar posições, selector, ranks ou última camada continua a falhar. Uma exceção do callback inclui nome/op/linhas para diagnóstico. O protocolo, dados, métricas, custo e limiares do C110 permanecem os mesmos. Uma nova identidade e nova checkout limpa são obrigatórias para a tentativa de evidência física, após o dry-run. A alteração é exclusivamente de observabilidade do cliente.

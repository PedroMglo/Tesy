# Ler só os intervalos de gate solicitados

Pré-registo após o NO_GO do scratch via memcpy, antes dos novos braços. A referência continua a ser o serviço direto da mesma matriz fria C110 OFF288. A primeira experiência cobrou 518 524 928 B ao cgroup para fornecer 215 913 600 B. Vamos testar se a leitura explícita dos mesmos 33 intervalos serve o banco mais cedo, já incluindo o tempo de materialização. [Resultado que motiva a intervenção](README.md)

Usar as mesmas fatias, slots, scratch, sentinelas, referência independente, alinhamento, CUDA 13.3/620.73.04, limites C55/C118 e restauração da [primeira experiência](protocol.md). Voltar a medir DIRECT contemporaneamente. PREAD_SEQ lê cada intervalo pelo fd sequencial diretamente para a fatia do scratch e emite o mesmo H2D. PREAD_RANDOM executa o mesmo código, mudando só o conselho do fd para `POSIX_FADV_RANDOM`. Cada pread tem de devolver a totalidade dos bytes pedidos. O mmap integral da origem serve também para observar o estado inicial/final. A aplicação não altera o ficheiro. O Linux documenta uma janela de readahead dependente do conselho ao descritor. Os efeitos no NVMe e na barreira serão medidos aqui. [Linux man-pages, posix_fadvise](https://man7.org/linux/man-pages/man2/posix_fadvise.2.html) · [Linux man-pages, pread](https://man7.org/linux/man-pages/man2/pread.2.html)

Dois processos, ensaios DIRECT→PREAD_SEQ→PREAD_RANDOM e PREAD_RANDOM→PREAD_SEQ→DIRECT. Abrir de novo, expulsar a única matriz e exigir zero páginas residentes em cada um dos seis braços. O banco e o scratch têm o mesmo estado inicial, os mesmos custos de reserva e uma única barreira de serviço. A camada, o papel, as rotas e os dados são os do mesmo lote 144. Os seis D2H devem coincidir com cada um dos 33 hashes CPU e preservar ambas as guardas antes de interpretar tempos.

**Comparação primária.** GO para uma fixture subsequente com os três pesos da camada se PREAD_RANDOM for mais rápido até à última barreira e reduzir os bytes do cgroup face a DIRECT nas duas ordens. NO_GO para esta opção no corte se o tempo for igual ou maior nas duas ordens. Restantes resultados INCONCLUSIVE. Publicar a margem de custo adicional de cada par em ms, sem extrapolar para um pedido. Em separado, comparar PREAD_SEQ com DIRECT para avaliar a mudança de API e PREAD_RANDOM com PREAD_SEQ para isolar o conselho. O braço do meio fica nessa posição em ambos os processos. Usar as mesmas regras para descrever cada contraste secundário, sem o promover a candidato confirmatório.

Os relógios primários e os três contadores de leitura são os do lote 145.

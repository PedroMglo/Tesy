# M5 long CLI campaign: TIMEOUT, criterion not met

Objective and frozen policy: `research/M5-PREFLIGHT-20260926.md`, base lab commit `aa97129`. Original candidate `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, verified 120B MXFP4 GGUF, 24 slots/layer, GPU8, direct expert I/O, no preload/repack, context4096, batch256/microbatch32, greedy, eight fixed public prompts, one process with context reuse, 256-token cap per response, 18 GiB cgroup/zero swap and 1800-second timeout. Exact command, hashes and 1-second samples are in `results/target120b-gpu8-sustained24-01.json`; timing and thermal windows in `results/target120b-gpu8-sustained24-01-analysis.json`. Raw stdout/stderr/samples are local and untracked. This was a performance experiment, not a task-quality score.

Measured: the watchdog stopped the process at 1805.524 s including five seconds of graceful termination/kill. `stop_reason=TIMEOUT`, return code -9; only six of eight requests completed. Their decode rates were 2.644, 2.378, 2.753, 2.646, 2.640 and 2.628 tok/s, each for 256 generated tokens. Aggregate 1,536 tokens / summed decode time = **2.610 tok/s**; last three completed requests = 2.638 tok/s. Prefill tokens/time grew from 108/47.619 s to 651/273.130 s as the conversation context accumulated. The seventh request was in prefill at timeout; no timing/result for it or the eighth is invented. These six intervals suggest no decode-rate collapse over the observed 26.5 minutes, but the predeclared eight-request completion requirement failed. **M5_PERFORMANCE_TARGET_MET remains unproven** for this CLI configuration; the >2 partial rate is not reclassified as PASS.

Peak cgroup 11,549,519,872 bytes, RSS 11,798,310,912 bytes, GPU used 3,148 MiB total, zero process/cgroup swap, zero cgroup max/OOM events. Model FD remained O_DIRECT during decode. Maximum sampled CPU Tctl 91.125 C, NVMe composite 60.85 C and NVIDIA GPU 59 C. Five-minute median CPU Tctl rose from 64.1 C to 84.0 C by minutes 20–25, then 82.4 C in minutes 25–30; NVMe median was about 57.9 C thereafter. This is observed thermal behavior, not a proof of absence of throttling; clocks and chassis power limits were not measured. Final sampled process `read_bytes` was about 2.40 TB across prefill plus decode, not exclusive NVMe traffic. Per-request TTFT and per-token p50/p95 were not available from this CLI instrumentation.

The six completed requests generated 1,536 total tokens, but the final-answer section was absent in requests 3, 5 and 6 at the 256-token cap. The other three had final visible text; exact final-section token counts were not measured. Generated-token throughput must not be confused with time to a useful final answer. No context-truncation warning or backend error was logged before timeout, and completed request `truncated` fields were zero, but the seventh was incomplete.

Decision: retain the measured 24-slot M3 configuration, retain this TIMEOUT as a failed sustained campaign, and do not extend its timeout or drop prompts post hoc. The separately frozen target task-server run in `research/M6-PREFLIGHT-20260926.md` is the next discriminating gate for task benefit and, if its own explicit sustained conditions hold, an independently identified M5 configuration. No optimization intervention was added or reverted. Limitations: long-prefix numerical equality, physical device-exclusive traffic, per-tier bytes/hits, TTFT and complete eight-request sustained performance remain unknown.

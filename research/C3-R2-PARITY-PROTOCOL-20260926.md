# C3 R2 capture OFF/ON parity protocol

Frozen before the paired model runs. Compare target `log_medium` from `results/c2-target-numeric-v1.ids` (SHA-256 `8fb3aff447febaeaa5a8bdd0c485fd20d51d39fb6ac3e6ba4849eb4a664dbc23`) on the same pinned streaming backend SHA `1248fd8fa8cfebaece5ea992e4d951c1e18bb9d5`, GGUF SHA-256 `582bd40f6886200101f4c4ed9f25f3fe80cc14c86e9e2b37746cd8904a0c622d`, GPU8/32slots, context4096, batch256/ubatch32, CPU threads8, I/O4, O_DIRECT, no preload, no repack/op offload. The capture build is SHA-256 `dd78f24890df698215bc744fa085d1814e8d2824bb0601d5eda6dadd16ec3955`; the OFF probe binary and loaded libraries are hashed by the bounded runner before execution. The capture and OFF probe run in separate fresh processes/scopes, one at a time.

The callback-enabled arm captures the first prefill microbatch (32 input IDs; logits at prompt position 31) and the first incremental continuation after the complete 189-ID prompt (logits at position 189). The callback-disabled C2 probe records the same positions plus other rows, under identical input IDs and graph settings. Primary gate: full 201,088-float32 logit vectors at both named positions are **BITWISE_EQUAL**, with finite values, complete files, exact row mapping and no run failure. Secondary: captured activation/top-k/weights/FFN outputs from the two callback-enabled variants may be compared bitwise, but this cannot substitute for the OFF arm. No post-hoc tolerance. Neither parity arm is a throughput benchmark.

Each arm must end with zero swap/OOM/max/kill, no guard stop and a complete no-replace raw manifest. Resource envelope: unique scope memory.max18 GiB, memory.swap.max0, RSS<=17 GiB, GPU<=7000 MiB, MemAvailable>=6 GiB, CPU/GPU/NVMe<=95/80/70 C, timeout300 s. The one-second bounded runner samples are supplemented by cgroup peak and final events; sparse samples limit GPU peak certainty for very short runs. A mismatch or missing row is FAIL; repair requires new run IDs. Raw captures and logits remain local. No change to C1/C2 gates.

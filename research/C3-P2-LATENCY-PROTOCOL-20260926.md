# C3 P2 preload latency probe (prospective)

After the sustained target gate, measure observable response latency for the unchanged C2-D synthetic ticket prompts `workloads/c2_latency_prompts.json`, in fixed short→medium→long order. The official backend template and tokenizer must return 113/496/1522 prompt IDs and leave 512 output tokens within context4096; a mismatch fails this comparison. Each prompt has one verifiable CRITICAL OPEN ticket. No prompt prefix cache, one request at a time, same process, greedy temperature0/seed42, medium reasoning, max output512. The existing `c2_latency_client.py` records first text/reasoning/final SSE arrival, total wall, completion validity and total usage. SSE chunks do **not** measure per-token latency.

Server: 120B artifact and pinned streamed backend, GPU8/32 slots, b256/ub32, direct I/O, no repack/no op offload, preload **enabled** by absence of `LLAMA_MOE_STREAM_NO_PRELOAD`. `c3_launch_preload.py` checks full artifact hash, binary/libraries and frozen C3 sustained protocol; `run_bounded.py` enforces cgroup memory.max18 GiB/swap0, RSS17 GiB, GPU7000 MiB, MemAvailable6 GiB, CPU/GPU/NVMe<=95/80/70 C. Endpoint 127.0.0.1:18367. One fresh server, no model overlap, no global cache clearing. Timing starts after the model is ready; expert/page cache may warm across the three requests and this is recorded as ordered-service, not three cold starts.

Output root is a new no-replace run ID. Stop the owned server after client completion, then require a complete monitored manifest with no stop/resource/telemetry errors. Comparison to C2-D is historical, not a causal same-day A/B; this probe is to verify whether reduced native prefill translates to earlier user-visible text on the same fixed prompts. If it fails or lacks required evidence, keep the first-text metric NOT_MEASURED for preload.

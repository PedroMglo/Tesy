# C20: cache OFF/ON paired prefix screen

- Objective/base: quantify the contribution of the C19 exact-prefix mechanism to the second 641-ID synthetic request. Base `30dfb1d`; C19 ON-only 510/510 reuse is a mechanism observation, not a paired speed result. Evidence at freeze: source/input identity checks, 10 model-free tests, new physical preflight; no C20 model run yet.
- Hypothesis: keeping the same 510-ID prefix in the server KV cache reduces completion-fenced time for the second request. Alternative: ambient/background variance, warm expert pools or different output trajectories explain the apparent C19 time, or cache OFF still reuses the prefix. Fresh processes, matched idle starts and reversed pair order address these alternatives within a small screening scope.
- Freeze: original model/backend/binary/libraries, C13 prefix input bytes and official tokenizer, P12 ngl12/ub32/slots32/preload ON, 8K/full-SWA, same first request, same E18/zero-swap, CPU100 warning policy and GPU/NVMe/RAM guards. Only the second request's `cache_prompt` flag is OFF/ON. Runs are OFF→ON; ON→OFF. Each arm uses one process and two sequential requests after >=300 s continuous idle admission.
- Gates and metrics: first request must have `cache_n=0`; second OFF must have `cache_n=0`, ON >=450 and <=actual common prefix. Full response, token IDs, output-message equality across arms, raw/provenance/mapped-library/telemetry and resource gates are mandatory. Primary metric is completion-fenced second-request elapsed seconds; paired gain `100*(OFF-ON)/OFF`. Screening passes if median of two paired gains >=20%, each positive and median first cold-request gain >=-5%. These are investment thresholds, not significance. A survivor needs three new confirmation pairs in order OFF→ON; ON→OFF; OFF→ON, with the same 20% median/positive pairs/first-cold rule.
- Claim limits: this synthetic timing screen cannot certify full-logit equivalence, real session quality, first final content, sustained service or M3. C15 remains source-only. Any fidelity/guard/telemetry failure stops its arm and is preserved; no hidden retry or threshold change.
